# 多分组与批量参数配置方案

设计 v1.3 · 2026-09-23｜实现基线：v23 前端原型

当前每组保存完整 JSON。后续建议采用“固定基线 + 各组覆盖”的编辑模型，提交与执行仍展开为每组完整配置；这项编辑模型尚未实现。

## 2. 不变的范围规则

- 生产 Namespace 直接承接旧项目，不叠加 project／space；参数 Key 在 Namespace 内唯一，归属一个应用，标签应用私有。
- 参数先 pending，目标环境完整归层后 active。域切流量、层分参数，同域参数完整且唯一，子域继承父层全部范围。
- 同一实验只能选择一个合法参数层内的参数，可跨应用，不可跨层或 Namespace 引用。
- 所有组配置同一顶层 Key 集合。object／array 内部路径不自动成为独立参数，也不能分别归层。
- 完整配置的编排、提交和发布按阶段检查实验动作、层 use、全部参数／受众／指标的必要 read/use，未完成草稿可先保存；能编辑实验不代表能编辑参数目录。见[权限设计](./服务端技术方案/05-Namespace与权限设计.md)。

一期授权直接绑定个人／机器身份，完整保留 Namespace 与多空间成员；用户组、组绑定、权限缓存和通用策略注册框架后续扩展。

每层 10,000 碎片桶、旧桶稳定、固定资格桶复用等分流规则不因编辑器升级改变。画像目录独立，不要求来源应用。

## 3. v23 编辑行为

| 项目 | 当前规则 |
| --- | --- |
| 保存对象 | 每个分组的完整 JSON 原文，顶层必须为对象 |
| 严格检查 | 语法、重复解码 Key、有限数、最多 32 层；错误可定位，错误原文仍保存 |
| 目录 | 最多显示 5,000 节点，完整内容仍校验与比较；JSON Pointer 定位，不按点号拆 Key |
| 筛选 | 仅改变显示；切应用清标签条件，不丢跨应用选择或草稿 |
| 会话状态 | 每组保留本次光标、折叠、滚动、撤销；刷新仅恢复原文 |
| 差异 | 忽略空白和对象字段顺序，数组整体比较，缺失与 null 分开 |
| 无效组 | 停止对应比较，不用上次有效值冒充当前文本 |
| 批量加入 | 保留已有值，新 Key 从登记默认值初始化；所有组完整检查 |

当前默认值不是线上基线，“比较基准组”不是配置继承。目录只读，差异不应用补丁或自动合并。

## 4. 固定基线工作流（规划）

```text
选择合法参数集合 → 选择并冻结基线来源
→ 建立 2–20 组 → 只编辑覆盖
→ 检查全部组与差异 → 展开并冻结完整分组配置
```

| 概念 | 明确语义 |
| --- | --- |
| 基线 | 配置起点，不占实验流量；不等于统计对照组 |
| 对照组 | 唯一实际比较组，可以显式覆盖基线 |
| 继承基线 | 无本组覆盖，跟随本次已冻结基线 |
| 显式覆盖 | 即使值与基线相同，也保留覆盖身份 |
| 恢复基线 | 显式移除本组覆盖，不能由空白或 null 推断 |

基线可来自有版本的完整配置、旧实验某组或显式选用的登记默认值。冻结来源、时间、Key 集合和定义版本；额外 Key 明确排除，缺少 Key 必须补齐，不能运行时读取最新默认值。跨应用基线记录各来源版本，再形成同一实验快照。

模板更新不会影响草稿或运行实验。“更新基线”须显示旧基线、新基线、覆盖和有效值差异；继承项可确认跟随，显式覆盖保持。字段删除、类型或 Schema 冲突阻止更新。

## 5. 参数表格与 JSON 视图（规划）

```text
已选 Key／应用数 · 固定基线版本
分组：A 对照 | B | C | D       比较：基线／对照／所选组
搜索 Key／路径 · 应用 · 私有标签 · 仅看差异／全部
参数与类型 | 基线 | 当前组覆盖 | 完整有效值
复杂参数 → 树／源码／差异
底部：全部组错误汇总、隐藏选择数量、完整配置预览
```

- 普通参数按 string／number／boolean 编辑；枚举只有有效 Schema 时提供。
- `0`、`false`、`""` 是明确值，编辑中空白不能自动转为这些值。
- 20 组按需选择比较，不挤入一屏；虚拟列表按稳定 Key／组 ID 保存状态，隐藏内容仍检查。
- 批量设值、复制、恢复基线必须明确 Key 和分组集合，失败保持原稿；筛选不充当隐式全选。
- 可编辑树和源码共享草稿；无效源码切换视图时不能丢弃，不能显示旧有效对象冒充当前结果。

复杂参数例如 `ranking.strategy` 内的 `/scenes/home_feed/recall/routes/semantic/enabled` 只是对象路径。长期需要独立实验或发布的场景可评估拆顶层 Key，但须显式迁移参数和消费者，不能自动拆分所有叶子。

首阶段即使改叶子，覆盖仍保存完整顶层参数值。数组整段替换，不按下标合并、不猜测 id、不自动去重；null 是真实值，不是删除标记。后续路径级覆盖需明确设置、删除、恢复继承、基线摘要和冲突规则。

## 6. 字段 Schema（规划）

保留现有 JSON 与顶层类型校验，再按不可变 Schema 版本逐步增加字段类型、必填、枚举、范围、长度、额外字段及数组约束。

| 情况 | 行为 |
| --- | --- |
| 历史参数无 Schema | 明确显示仅检查 JSON 与顶层类型，不突然失效 |
| 未支持的关键字／脚本／远程引用 | 拒绝启用或明确不支持，不能静默忽略后显示通过 |
| 跨字段业务关系 | 另行声明校验能力与版本，不假定类型检查已覆盖 |
| 校验器超时 | 报告未完成，不当作通过 |
| default 注释、缺失值 | 不自动补写，缺失／null／空字符串分别处理 |
| 新 Schema 版本 | 不重写旧定义、实验或运行快照 |

Schema 是参数内部结构与可执行性约束，不重新引入已下线的任意参数组合规则。

## 7. 批量导入（规划）

首期考虑 JSON 和明确结构的 CSV；CSV 至少含 `group_id`、`parameter_key`、`action`、`value_json`，值按 JSON 保留类型。

| 模式 | 文件语义 | 未出现项 |
| --- | --- | --- |
| 更新覆盖 | set 或 inherit；set 必须有值，inherit 不带值 | 保持原稿 |
| 完整组配置 | 所选组全部声明 Key | 缺任一 Key 报错 |

流程：

1. 检查编码、格式版本、体积、重复 Key 和结构限制。
2. 核对 Namespace、实验、草稿 revision、稳定组 ID 与参数范围；未知目标不自动注册或归层。
3. 严格检查值和固定 Schema，不转换类型、不删未知字段、不用默认值补缺。
4. 在副本中展开并验证全部组；重复目标、父子路径冲突、任一错误均整批失败。
5. 展示影响组／Key／路径及完整差异，包括隐藏筛选项。
6. 应用时再次检查权限、草稿版本、拓扑和目录；通过后一次替换，失败保留原稿，可撤销整批。

导入不自动提交、占桶或发布。首期不通过文件删除顶层声明 Key；改变参数集合走独立流程。建议以 1,000 Key、20 组和大对象做容量测试，但这不是当前容量承诺；超出实测上限须明确拒绝或使用服务端存储。

## 8. 完整快照与运行

草稿保存固定 Key、基线内容及来源、稳定组 ID／角色／权重、覆盖、定义／Schema 版本和 revision。生产提交解析为每组完整有效值，与实验 revision、分析计划及实际指标口径一起冻结到 `experiment_run`，通过 `change_request` 按摘要审批；`metric` 当前定义更新不改变旧 run。

一期控制库为 30 张物理表，不含事件湖仓事实表。配置快照、参数包和服务投影在对象存储保存，不逐类建表；详见[数据库设计](./服务端技术方案/01-数据库设计.md)。这不改变完整快照、运行签名、租约、撤销或桶 draining 要求。

“完整”仅指本实验声明的 Key，不是整个目录。执行端不动态拼接最新模板；参数、权重、资格、分析计划变化创建新 run。跨应用同时生效还需要配置就绪、同一 decision、执行报告与联合回退，不能由编辑器原子保存推断。

运行端仍区分 assignment 与 exposure；机器授权、真实发布及事件链路见[SDK 协议](./服务端技术方案/03-SDK与分流协议.md)。

## 9. 分期与验收

| 阶段 | 内容 | 关键验收 |
| --- | --- | --- |
| v23 已有 | 源码、只读目录、实际组间差异、本地草稿 | 现有历史记录见 VERIFICATION |
| 下一阶段 | 固定基线、表格、顶层覆盖、预检导入与整批撤销 | 隐藏项不丢；缺 Key／错类型／重复目标整批失败；陈旧预检拒绝 |
| 后续 | 不可变 Schema、可编辑树、业务显示元数据 | 无效原文不丢；数组变化清晰；Schema 新版不改旧快照 |
| 按需扩展 | 外部基线、明确身份的数组操作、领域校验器 | 版本和冲突可追溯，不隐式深合并 |

跨阶段验收：20 组少量变化可准确审查；模板不漂移；存储失败不修改原稿；导出的完整组值可与审批快照逐项对应；生产权限不得被导入或批量操作绕过。

实现入口：`CreateExperiment.tsx`、`ExperimentGroupsEditor.tsx`、`JsonParameterWorkbench.tsx`、`json-parameter-analysis.ts`、`experiment-draft-validation.ts`。早期参数设计见[历史规格](./superpowers/specs/2026-09-12-service-owned-parameters.md)，不以旧字段或版本记录替代当前约束。
