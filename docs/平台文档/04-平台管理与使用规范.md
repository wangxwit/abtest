# EXP Lab 平台管理与使用规范

设计 v1.2 · 2026-09-23｜实现基线：v23 前端原型

本规范区分组织责任和系统授权。v23 只有本地校验、负责人和期限字段；Namespace、RBAC、审批、审计与发布控制属于未实现的生产设计。授权细则以[05 Namespace 与权限设计](../服务端技术方案/05-Namespace与权限设计.md)为准。

## 1. Namespace 划分

Namespace 是完整实验资源与授权作用域，直接承接旧项目，不叠加 project／space，也不等同团队。平台为单企业部署，不设租户实体。

| 情况 | 划分建议 |
| --- | --- |
| 招聘、房产、本地生活各自独立业务流程 | 可分设 Namespace，各自维护目录、环境、拓扑与凭证 |
| 同一首页共用画像、混排和参数 | 放在同一消费者 Namespace，按资源向团队授权 |
| 一个团队维护多个独立产品 | 可加入多个 Namespace，不按团队强制合并 |
| 多团队维护同一参数组合 | 同一 Namespace 内授权协作，不复制参数到多个空间争抢控制 |

不同 Namespace 隔离资源、配置、权限与分桶空间，但同一业务用户可以同时参与多个 Namespace。分桶独立不保证流量互斥或业务效果独立；跨 Namespace 不直接引用参数／层。确需联合控参时先确定唯一控制归属和迁移方案。

## 2. 责任与权限

| 责任主体 | 组织职责，不自动授予权限 |
| --- | --- |
| 平台管理员 | 全局账号、角色模板、可委派权限边界、平台运行保障 |
| Namespace 管理员 | 本空间成员与获准范围内的角色绑定、资源治理 |
| 应用负责人 | 参数定义、执行兼容性、默认行为与接入维护 |
| 层域负责人 | 参数分区、流量计划、依赖和资源期限 |
| 实验负责人 | 假设、分组、分析计划、运行与结论 |
| 审批人 | 核对指定版本、影响范围和发布条件 |
| 数据负责人 | 指标口径、数据质量、分析与复现 |

全局账号可加入多个 Namespace；账号和用户组可在获准 Namespace 内多次绑定角色。组绑定只对同时具有有效 Namespace 成员资格的个人生效。`namespace_member` 仅准入，不自动看全部资源。

```text
有效授权 = 成员准入
         + 角色动作集
         + 资源范围
         + 可选环境限制
多个 allow 取并集；默认拒绝；不设计显式 deny。
```

- 角色模板由平台管理；Namespace 管理员只能授予获准委派的角色与范围。
- 权限仅沿资源归属树继承：应用→参数，环境→域→层→实验。
- 引用关系不继承：能用层不代表能编辑关联参数；owner、创建者、标签均不自动赋权。
- 父级编辑不能由子级只读覆盖。若需收窄，修改原始广域授权，不叠加“只读”假装撤权。
- 环境授权不自动授予 Namespace 目录全局编辑权。

| 分离的权限 | 管理要求 |
| --- | --- |
| 目录管理 / `parameter.use` | 使用参数不必拥有定义编辑权 |
| `layer.manage` / `layer.use` | 调整层结构与在层内实验分别授权 |
| `experiment.edit` / `approve` / `publish` | 编辑、审批、发布不能互相替代 |
| `result.read` / `result.export` | 可看结果不等于可导出 |

多资源操作按阶段检查全部必要权限。完整配置的编排、提交和发布需要相应实验动作、目标层 use，以及全部参数／受众／指标的必要 read/use；未完成草稿可先保存。审批只要求所需 read + approve，不要求 edit/use；发布重新校验生产授权及有效审批。列表、详情、搜索、导出均在后台过滤并留审计，原型按钮不是安全控制。

机器身份另按 Namespace、环境、服务和动作授权，不能复用人的成员身份或把凭证放进浏览器配置。

## 3. 参数与目录治理

1. 在所属应用登记参数，Key 在 Namespace 内唯一；按独立实验／发布边界确定粒度。
2. object／array 的顶层 Key 是最小归层和覆盖单元；内部路径不能由不同层同时控制。
3. 参数注册为 pending，在目标环境一次完成全部受影响域归属后原子 active。
4. 同域参数完整且唯一归层；转移前检查未结束实验、子域继承和消费者依赖。
5. 应用私有标签只做分类；不按 Key 前缀猜归属，也不让标签维护改变运行配置。
6. 画像属性独立登记，不要求来源应用；冻结类型、统计口径与受众引用版本。
7. 定义、Schema、默认值、模型或索引变化走版本化评审，不静默改变旧 run。

原型参数默认值只是编辑初值；参数定义编辑／删除和服务迁移未实现。不要通过另建同义 Key 绕过依赖保护。

## 4. 层域治理

根域只有一个路由层，路由层只承载子域；域→层→实验／子域递归，最大域深度 16。

| 需求 | 选择 |
| --- | --- |
| 改同层参数 | 复用该层建实验 |
| 稳定能力需要经常并行迭代 | 在重叠域划分参数互斥的长期层 |
| 为某参数范围留出互斥流量 | 在覆盖该范围的父层下建子域 |
| 偶发跨层联合方案 | 使用覆盖所有目标参数的联合实验域 |
| 反复出现同类跨层组合 | 实验结束后评审并版本化调整参数边界 |
| 临时探索 | 优先复用；确需新资源则登记负责人及到期日 |

子域创建只生成一个继承全部参数的初始层，之后再拆分。空层可保存，但不能开实验或建子域。非重叠子域只隔离所在分支；根路由兄弟分支才可在本 Namespace 内隔开全部参数层。

负责人和期限定期复查；原型临时资源日期仅提示，不自动停止实验、删除资源或释放桶。

## 5. 共享首页示例

```text
消费者 Namespace / 生产环境
根域 → 唯一根路由层
  ├ 日常实验域
  │ ├ 公共画像层
  │ ├ 混排层：跨业务配额、多样性、价值换算
  │ ├ 招聘策略层
  │ ├ 房产策略层
  │ └ 本地生活策略层
  ├ 联合实验域 → 完整参数层 → 单个联合实验
  └ 长期保留组域（可选，定义参考策略与固定成员）
```

画像和混排只有在参数可独立变更时拆层；需要成套修改时合层。`home.mix.jobs_quota` 改变所有业务展示机会，属于公共混排，不能仅因名称含 jobs 放到招聘层。

日常域正交分配估计当前其他实验组合下的平均效果，不能把收益相加。可能存在强交互时，可在联合域配置单实验四组：基线、只改混排、只改招聘排序、两者都改。四组配置不代表已有正式交互检验；指标一期的对照比较与 Holm 校正不能替代交互分析，需预先定义并扩展分析计划及计算实现。例子见[联动实验设计](../联动实验设计.md)。

## 6. 流量与受众

- 每层 10,000 固定桶，按总量组合空闲碎片，不移动旧桶；并行层占用不能相加。
- 同层直接实验与子域共享账本；预览不预留，提交时重新检查。
- 仅相同固定资格语义下可证明互斥的完整条件才能复用桶；动态画像、估算比例不能代替证明。
- AND／OR 必须包含全部祖先域条件；unknown 按可能冲突处理，执行时不视为满足。
- 资格不符不换桶补量；名义份额不承诺实际人数。
- 主分析按处理前资格定义，不按实验后的点击或帖子曝光筛选样本。

生产状态以冻结 run 和发布状态管理：待审、运行、暂停可保留桶；结束后进入 draining，确认旧配置和决策上下文失效才回收。原型结束即本地释放的行为不作为生产协议。

## 7. 联动、发布与审计

```text
固定目标与分析计划 → 选择合法层及参数 → 校验并预留
→ 审批精确版本 → 校验服务就绪与生产权限
→ 编译签名快照 → 激活发布 → 观测执行与数据质量
→ 停止签发 → 等待有效期和观察窗 → 回收／归档
```

- 参数值、组权重、资格、分析计划改变创建新 run；新内容使旧审批失效。
- 跨服务复用同一 decision；校验真实执行、模型版本、缓存和回退，不以“同 user_id”推断一致。
- assignment 不等于 exposure；分配后失败和回退保留在预定 ITT 主分析中。
- 共享模型训练、画像写回、库存／岗位／房源竞争不受域分流自动隔离，需单独实验设计。
- 紧急停止记录操作者、原因、版本和覆盖；无法撤回已发生的业务副作用。
- 结果附指标、分析代码、配置和数据水位版本；异常与重算不能静默覆盖历史。
