# 服务端接口协议

版本：设计基线 v1.0｜日期：2026-09-19｜对照原型：v23。

本文是待实施的服务端协议，供管理前端、控制服务、配置分发、SDK 与采集服务共同实现。当前仓库只有前端交互原型，本文所有 HTTP 路由、身份认证、事务、配置签名及事件接收能力均尚未实现。原型行为依据 [README](../../README.md) 与 [现有技术方案](../平台文档/02-技术方案.md)；生产约束以本组服务端设计为准。

## 1. 范围、身份与版本

### 1.1 资源作用域

令 `P = /api/admin/v1/projects/{project_id}`，`E = P/environments/{environment_id}`。下文路径表中的 `P`、`E` 为文档缩写，不能原样发送。管理 API 使用 OIDC Bearer access token；服务端从身份会话解析 `tenant_id` 并校验项目关系，不能以请求体或自定义头中的租户 ID 代替授权。

| 作用域 | 资源 | 必须保持的边界 |
| --- | --- | --- |
| tenant | 成员、角色、项目与组织策略 | 项目不得跨租户引用资源 |
| project | 应用／服务、参数定义与版本、应用私有标签、画像属性与版本、受众与固定版本、指标定义与版本 | 参数 Key 在项目内唯一；所属服务一经确认不可直接改写 |
| environment | 服务接入配置、参数归层状态、环境基线、域层拓扑、实验草稿／实验／运行、桶预留、审批、发布、分析结果 | 开发、测试、生产分别授权和分配，不共用桶账本、发布指针或运行状态 |

项目级参数在指定环境的状态为 `pending` 或 `active`。注册参数不要求选层，也不自动扩张任何环境拓扑；对一个环境的首次激活，必须在一次事务内完成该环境所有受影响域的归属。参数目录显示环境状态时必须显式指定 `environment_id`，不能把生产环境归层结果当作项目级唯一状态。

管理路由中对象的项目、环境、服务归属必须逐层校验。无权知道是否存在的对象返回 `404`；同一授权范围内但权限不足返回 `403`。应用标签是业务分类，不授予参数读写或发布权限。

### 1.2 基础类型与标识

| 字段／类型 | 协议定义 |
| --- | --- |
| JSON 字段 | `snake_case`；`Content-Type: application/json`；UTF-8；未知请求字段默认拒绝，客户端忽略未知响应字段 |
| `*_id` | opaque string，不解析前缀、位数、顺序或业务含义；示例前缀仅便于阅读；路径段按 URI 规则编码 |
| `revision`、`experiment_revision`、`allocation_revision` | 从 1 开始的单调整数；分别为资源乐观版本、不可变实验内容版本与同 run 分配映射版本，不能混用 |
| `config_revision` | 不可变配置产物标识字符串；不按字典序比较；发布顺序用独立的 `release_sequence` 整数 |
| 时间点 | RFC 3339 UTC，例 `2026-09-19T15:00:00.000Z`；不传本地无时区时间 |
| 日期 | 管理信息的 `expected_end_date` 为 `YYYY-MM-DD`；按环境继承的项目 `timezone` 计算提醒，不代表 UTC 时间点 |
| 比例 | `*_bps` 为整数 `0..10000`，1 bps = 0.01%；分组权重必须大于 0，全部组之和等于 10000 |
| 桶段 | `{ "start": 0, "end": 1000 }`，整数、左闭右开，`0 <= start < end <= 10000`；返回值已排序、合并相邻段且无重复 |
| 金额与精确小数 | 用带单位的十进制字符串或明确整数最小单位；不得依赖 JSON 浮点数表示财务精度 |
| 可空字段 | 未提供表示不修改；显式 `null` 仅用于 Schema 声明可清空的字段；不把空串、缺失与 null 混为一谈 |

`experiment_id` 是长期业务身份；`run_id` 是一次固定受众、随机化单元、分组、参数值与指标方案的运行身份；`experiment_revision` 是审批及编译绑定的不可变内容。权重、参数值、受众或统计方案变化创建新 run；扩量只有在保留旧桶、旧用户分组及所有固定方案时，才可在同一 run 新建 `allocation_revision`，不改变 `experiment_revision`。暂停、恢复不创建新 run；已完成 run 不重新开启。

### 1.3 成功响应、分页与条件读取

单资源返回 `{"data": {...}, "meta": {"request_id": "..."}}`；集合返回 `data` 数组及 `page`。创建成功为 `201` 并返回 `Location`；异步命令为 `202` 并返回任务地址；查询和同步更新为 `200`。HTTP `request_id` 为服务端追踪号，独立于运行评估请求体中的业务重试 `request_id`。

```json
{
  "data": [
    {"experiment_id": "exp_feed", "name": "推荐策略实验", "current_run_id": "run_feed_1", "state": "running"}
  ],
  "page": {"limit": 50, "next_cursor": "cur_opaque", "has_more": true, "read_snapshot_id": "read_opaque"},
  "meta": {"request_id": "req_admin_1"}
}
```

所有集合使用 `limit`（默认 50，最大 200）与 opaque `cursor`；游标绑定租户、项目、环境、过滤条件、排序和一致读取位置。默认按 `created_at desc, id desc` 排序；禁止客户端通过任意 SQL 字段排序。过滤条件改变必须清空 cursor；游标过期返回 `409 CURSOR_EXPIRED`，重新从首屏读取，不偷偷接续另一数据集合。默认不返回昂贵的精确总数。

可编辑资源和拓扑读取响应返回强 ETag。更新必须原样发送 `If-Match`；漏传返回 `428 PRECONDITION_REQUIRED`，过期返回 `412 REVISION_MISMATCH`。只读条件获取使用 `If-None-Match`，未改变返回无 body 的 `304`。带 ETag 的 GET 表示不包含逐请求变化的 `meta.request_id`，追踪号只写 `X-Request-ID` 响应头，以免强验证器与实际表示不一致；其他响应可使用 meta。ETag 是不透明表示验证器，不允许客户端自行由 revision 拼接。HTTP 条件请求沿用 [RFC 9110 §13](https://www.rfc-editor.org/rfc/rfc9110.html#section-13)。

### 1.4 幂等、并发与重试

创建及命令类 `POST` 必须带 `Idempotency-Key`；纯查询的 `:check`、`:preview`、`:validate`、模拟接口除外。幂等命名空间为 `(tenant_id, project_id, environment_id?, caller_id, method, canonical_path, key)`，服务端存储请求摘要、执行状态和原始响应。外层 JSON 按稳定规范化计算摘要；草稿源码字符串保留原文字节含义，不能先解析丢失重复字段或格式。

- 同键同内容：返回同一资源／任务和原响应，响应头 `Idempotent-Replayed: true`。已成功的重试先读取幂等结果，不因原 `If-Match` 已旧而再次执行。
- 同键不同内容：`409 IDEMPOTENCY_KEY_REUSED`；同键仍在执行：`409 IDEMPOTENCY_IN_PROGRESS`，按 `Retry-After` 以原键重试。
- 幂等记录的最低保留期为 24 小时，并在响应声明 `Idempotency-Key-Expires-At`；客户端不得复用旧键。草稿提交另有持久唯一关系 `source_draft_id → experiment_id/run_id`，不能只依赖短期缓存防重。
- 版本检查、占桶、状态更新、审批绑定、审计和 outbox 在同一数据库事务完成。`preview_id` 与前端通过提示不持有数据库锁，不构成流量保留。
- `429`、`503`、网络超时：在整体截止时间内按 `Retry-After` 或指数退避加随机抖动重试，写请求保留同一键和内容。`409` 领域冲突、`412`、`422` 需要重读或修正，不能无限原样重试。`401` 仅允许刷新凭证后重试一次。

## 2. 项目目录 API

### 2.1 应用与接入

| 方法与路径 | 请求／返回重点 |
| --- | --- |
| `GET /api/admin/v1/projects` | 返回调用者获授权的项目；不能列出其他租户项目 |
| `GET P/environments` | 环境目录、时区、授权能力，不包含凭证 |
| `GET/POST P/services` | 列表／登记；`name, service_key, service_type, owner_id`；`service_key` 项目唯一 |
| `GET/PATCH P/services/{service_id}` | 查看／更新管理资料；`If-Match`；类型为 `frontend/backend/strategy/gateway` |
| `GET/PUT E/services/{service_id}/access-config` | 接入配置：`mode=direct\|delegated`，委托时填 `gateway_service_id`；跨环境、非网关或循环委托拒绝 |
| `POST E/services/{service_id}/access-config:verify` | 返回 `verification_task_id`；通过真实握手、配置装载和权限验证产生状态 |
| `GET E/services/{service_id}/observations` | 按时间窗返回真实接入与版本观测；无数据时返回空集合和 `data_status=no_data` |

接入配置的 `verification_status=pending|verified|failed` 为服务端只读字段，保存配置会使旧验证失效；UI 不能写入“已连接”。用户只通过受控身份平台获得短期工作负载凭证；响应、审计、日志和浏览器存储均不返回机器私钥或生产 secret。

### 2.2 应用私有标签与参数

| 方法与路径 | 语义 |
| --- | --- |
| `GET/POST P/services/{service_id}/tags` | 本应用标签；名称去首尾空白后在应用内唯一；其他应用可以同名但 ID 不同 |
| `PATCH P/services/{service_id}/tags/{tag_id}` | 名称／颜色更新，`If-Match`；不能移动到其他应用 |
| `POST P/services/{service_id}/tags/{tag_id}:archive` | 归档分类，保留历史关系；不改实验固定参数集 |
| `GET/POST P/services/{service_id}/parameters` | 本应用参数列表／登记；注册不接受 `layer_id` |
| `GET P/services/{service_id}/parameters/{parameter_id}` | 固定服务归属、Key、当前定义版本、标签、各环境归层状态和引用摘要 |
| `PUT P/services/{service_id}/parameters/{parameter_id}/tags` | 完整替换标签 ID 集；逐一校验属于当前服务；不改变运行快照 |
| `POST P/services/{service_id}/parameters/{parameter_id}/versions` | 新建不可变定义版本；运行引用不跟随“最新”漂移 |
| `GET E/parameter-candidates` | 为跨应用同层选参提供授权候选，返回不可选原因；不是全局参数维护入口 |

参数列表过滤支持 `q`（Key／登记名称）、重复 `tag_id`（任意匹配）、`environment_id`、`layer_id`、`activation_status`。跨应用候选接口支持 `service_id`；带标签过滤时必须同时指定该标签所属 `service_id`，否则 `422 TAG_SCOPE_REQUIRED`。编辑器切换应用不应删除跨应用累计选参；最终实验保存固定的 `parameter_ids`，标签修改不追踪增删。

登记请求示例：

```http
POST /api/admin/v1/projects/prj_shop/services/svc_rank/parameters
Authorization: Bearer <oidc_access_token>
Idempotency-Key: register-ranking-temperature-1
Content-Type: application/json
```

```json
{
  "key": "ranking.temperature",
  "name": "排序温度",
  "value_type": "number",
  "default_value": 1,
  "safe_default_value": 1,
  "schema": {"$schema": "https://json-schema.org/draft/2020-12/schema", "type": "number", "minimum": 0.1, "maximum": 2},
  "owner_id": "usr_owner",
  "tag_ids": ["tag_rank_tuning"]
}
```

```json
{
  "data": {
    "parameter_id": "par_temperature", "service_id": "svc_rank", "key": "ranking.temperature",
    "parameter_version_id": "pv_temperature_1", "revision": 1,
    "environment_bindings": [{"environment_id": "env_prod", "activation_status": "pending"}]
  },
  "meta": {"request_id": "req_register_1"}
}
```

`value_type` 为 `string|number|boolean|object|array`。顶层 null 不属于这五种类型；嵌套 null 是否允许由 Schema 决定。参数 Schema 采用 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core)，初期只开放审核通过的类型、枚举、边界和对象结构关键字；禁止运行时拉取外部 `$ref`、任意脚本或自定义远程校验。能力接口声明支持的关键字，不支持的关键字明确拒绝。默认值和各实验值都要通过固定定义版本校验；这属于单参数合法性，不能重新引入已下线的跨参数组合约束。

`default_value` 用于新配置初填；运行默认值来自不可变环境基线：`GET/POST E/baselines`、`GET E/baselines/{baseline_version_id}`。新基线仍需审批与发布，不能通过参数目录编辑即时改线上值。

可选 `safe_default_value` 属于参数执行契约，与定义版本一同冻结并通过类型／Schema 校验；接入代码在部署时确认并携带该安全值，运行故障时无需联网读取。改变它不能自动热改调用方的应急逻辑。首版目录、实验只设一个 `owner_id`；协作者由授权关系管理，不把数组负责人截成第一个写库。

## 3. 画像属性与受众 API

| 方法与路径 | 语义 |
| --- | --- |
| `GET/POST P/profile-attributes` | 属性目录；Key、类型、允许值、来源契约与缺失语义；与实验参数独立 |
| `POST P/profile-attributes/{attribute_id}/versions` | 新建固定语义版本，不能原地重解释旧快照中的值 |
| `GET/POST P/audiences` | 受众身份与管理资料 |
| `GET/POST P/audiences/{audience_id}/versions` | 固定条件版本；新版本始终运行服务端条件检查 |
| `POST P/audience-conditions:check` | 检查表达式自身、矛盾和目录关系；可携带环境／层上下文 |
| `GET P/audiences/{audience_id}/versions/{audience_version_id}/references` | 直接域引用，以及按环境汇总的实验直接／祖先引用 |

条件 AST 的组节点是 `{"kind":"group","operator":"and|or","children":[...]}`；规则节点是 `{"kind":"rule","attribute_version_id":"...","operator":"in","value":[...]}`。允许操作符由登记类型给出；布尔只接受布尔，数值只接受有限数，集合必须非空。新条件树限制三层分组、30 条规则；未知属性、未解析历史条件不得自动变为“所有用户”。

`audience-conditions:check` 请求和返回：

```json
{
  "condition": {
    "kind": "group", "operator": "and",
    "children": [{"kind": "rule", "attribute_version_id": "av_country_1", "operator": "in", "value": ["CN"]}]
  },
  "context": {"environment_id": "env_prod", "layer_id": "lyr_rank", "traffic_bps": 2000}
}
```

```json
{
  "data": {
    "valid": true, "satisfiability": "satisfiable", "relation_to_registered": "overlap",
    "ancestor_intersection": "satisfiable", "available_bucket_count": 7200,
    "required_bucket_count": 2000, "capacity_sufficient": true,
    "proof_status": "not_disjoint", "proof_engine_version": "proof_1",
    "checked_dependencies": {"topology_revision": 14, "layer_ledger_revision": 22},
    "warnings": [{"code": "AUDIENCE_OVERLAP", "message": "与已登记受众存在交集"}]
  },
  "meta": {"request_id": "req_audience_check"}
}
```

创建受众版本时接收相同 `context`，并重新执行上下文检查。自身矛盾、与祖先已知交集为空、当前申请桶数不足均返回 `422`，普通重叠只提示。没有上下文的项目级创建不能宣称某个环境有容量。`unknown` 不能当成 `disjoint`：OR 分支超过 64 组合或其他证明不足时，可以完整求值用户资格，但不得据此放行同桶复用。

固定资格依赖 `eligibility_epoch`、属性定义版本、可信画像快照和祖先受众版本。目录中受众版本不可变，但环境拓扑会变；提交及发布必须重读祖先版本与证明依赖。保存受众本身不保留桶；从内联保存到实验提交之间容量仍可能变化。

## 4. 拓扑、归层与流量 API

| 方法与路径 | 核心行为 |
| --- | --- |
| `GET E/topology` | 全部获授权域层、参数作用域、`topology_revision` 和 ETag；凭权限投影，修改方需有完整依赖视图 |
| `GET E/layers/{layer_id}/reservations` | 桶段、预留状态、所有者及受众证明摘要；已逻辑结束但 draining 的占用仍返回 |
| `POST E/parameters/{parameter_id}/activation-plans` | 返回全部受影响域、候选归属、阻断项、依赖版本；不修改状态 |
| `POST E/parameters/{parameter_id}:activate` | 提交每个受影响域唯一归属；锁定相关域层账本，原子激活，不能部分成功 |
| `POST E/domains/{domain_id}/layers` | 新建层，可空层或合法转移参数；同域完整分区、来源非空保护与依赖检查 |
| `POST E/layers/{layer_id}/child-domains` | 创建子域并原子创建初始参数层；自动承接父层全部参数 |
| `PATCH E/domains/{domain_id}/management` / `PATCH E/layers/{layer_id}/management` | 只改负责人、期限和日期，`If-Match`；到期不触发实验终止或回收 |
| `POST E/allocation:preview` | 计算有效受众、冲突与自动组合桶段，不保留桶 |
| `POST E/traffic:simulate` | 完整递归模拟；测试身份和画像只能进入沙箱，不写生产固定资格、曝光或分析数据 |

根域只允许一个全参数路由层且不承载实验；域层交替嵌套，域深度最大 16。同域层集合恰好划分继承参数范围，空层可保存但不得承载实验或子域。非重叠域及其后代保持单路径；非重叠分支不会隔离祖先的其他并行层。所有命令在数据库事务重校验这些不变量，不能让前端自行拼装可写拓扑树。

`child-domains` 接收 `name, mode, traffic_bps, audience_version_id?, management`，不接收初始 A/B 两层或任意删减的继承参数。`management` 为 `owner_id, lifetime=long_term|temporary, expected_end_date`；长期日期必须 null，临时必须有效日期，可为过去日期。初始层复制一次管理信息，后续独立维护。

归层计划的 `plan_id` 是建议结果，绑定 `topology_revision`、参数定义及相关层账本版本。`:activate` 发送 `plan_id`、`assignments:[{domain_id,layer_id}]` 和 `If-Match`；过期计划 `409 PLAN_STALE`，不尝试“尽可能激活”。已 active 参数不允许退回 pending 来绕过运行中实验与继承依赖。

流量预览示例：

```json
{
  "layer_id": "lyr_rank", "audience_version_id": "audv_cn_1", "traffic_bps": 2000,
  "expected_topology_revision": 14,
  "replacing_run_id": null
}
```

```json
{
  "data": {
    "preview_id": "preview_1", "reservation_created": false,
    "bucket_ranges": [{"start": 1000, "end": 1800}, {"start": 4000, "end": 5200}],
    "allocated_bucket_count": 2000, "available_bucket_count": 7200,
    "allocation_mode": "lowest_available_first",
    "topology_revision": 14, "layer_ledger_revision": 22,
    "proof_dependencies_digest": "sha256:example", "blocking_resources": []
  },
  "meta": {"request_id": "req_preview_1"}
}
```

每个层独立具有 `[0,10000)` 桶空间，桶段长度之和等于 `traffic_bps`。自动组合可用段，不压缩其他资源。只有同一可信固定资格策略下可证明互斥的候选可以重用桶坐标；draining 占用同样参与冲突判断。实验提交、子域创建和扩量提交才创建真实预留，均重新选桶／验证；用户在预览中看到的坐标不承诺最终相同。

模拟的 `focus_node_id` 只标记关注位置，不能改变根起点、身份、桶号或隐藏并行分支。返回 `paths[]`、首个阻断节点及 `reason`，并显式 `simulation=true`；“到达层”不等于命中实验。

### 5.4 审核与状态命令

以下以 `R = E/experiments/{experiment_id}/runs/{run_id}` 缩写路径。命令统一携带 `If-Match`、`Idempotency-Key`、`reason`，服务端执行权限及状态检查。

| 方法与路径 | 前置条件 | 结果 |
| --- | --- | --- |
| `POST R:approve` | `review`；精确 `experiment_revision + plan_digest + dependency_digest`；审批人符合职责策略 | 冻结批准记录，`approval_status=approved`；仍不开始处理 |
| `POST R:reject` | `review`，无已生效启动 | run 变 `completed`，`completion_reason=review_rejected`，返回新的可编辑 `draft_id` |
| `POST R:start` | `review` 且审批有效、预留有效、服务就绪 | 创建发布任务，目标 running；运行前不返回实验值 |
| `POST R:pause` | `running` 或已受理启动需由发布协调器串行处理 | 目标 paused，保留桶和分组，发布停止处理配置 |
| `POST R:resume` | `paused`，依赖仍有效、参数及分组契约未改 | 目标 running；沿用同 run 和原分组 |
| `POST R:complete` | `running/paused`，或显式取消未激活的 review | 目标 completed，停止新处理；预留进入 draining 或满足证明后直接释放 |
| `POST R/expansions:preview` | 原 run 合约未改；新 `traffic_bps` 严格增加 | 计算附加桶与新 allocation_revision，不保留 |
| `POST R/expansions` | 带原 allocation_revision、预览依赖和审批需求 | 创建同 run 新不可变 allocation_revision，保留 experiment_revision、旧桶、分组与 salt；审批发布后生效 |

`:reject` 不能把原 submitted 草稿改回可写，旧 run 不复活。只有能证明从未发布、未签发 token 的审核预留才直接 released；其他情况走回收栅栏。扩量审批绑定 `run_id + allocation_revision + allocation_digest + dependency_digest`，不改已批准的实验内容版本；扩量不修改既有 variant 区间映射；不能为了凑新的总体占比把旧用户重新分组。缩量、组权重／值／受众／分析计划变化必须新 run；第一期对存在冲突的替换 run，要等原 run 排空后才能取得相交预留，不默认给替换实验绕过账本。

状态命令返回示例：

```json
{
  "data": {
    "run_id": "run_feed_1", "state": "running", "desired_state": "paused",
    "publish_task_id": "pub_pause_1", "publication_status": "building",
    "reservation_state": "reserved", "all_instances_effective": false
  },
  "meta": {"request_id": "req_pause_1"}
}
```

这里 `state` 是最近已激活控制配置中的状态，`desired_state` 是正在执行的目标；`202` 仅表示受理。激活停止配置后 state 变 paused/completed，旧实例和在途上下文仍受有效期／撤销栅栏约束，不能据此声称全网瞬时生效。未激活前任务失败，原有效状态保持；激活后装载失败不回写“从未发布”，需要修复或显式回滚任务。新命令遇到同 run 未完成发布返回 `409 RELEASE_IN_PROGRESS`；紧急停止由专门命令获得协调优先权。

### 6.1 管理接口

| 方法与路径 | 语义 |
| --- | --- |
| `GET E/publish-tasks/{publish_task_id}` | 编译／分发／激活步骤、期望及观测版本、失败原因、区域与实例确认摘要 |
| `GET E/releases` / `GET E/releases/{release_id}` | 不可变发布历史与激活时间、来源审批、输入摘要、配置版本 |
| `POST E/releases/{release_id}:retry` | 只重试可恢复步骤；不可变输入不改，当前依赖不合法则明确失败 |
| `POST E/releases:rollback` | 指定目标历史版本与原因；校验桶回收、归属、撤销、兼容性后生成新发布任务 |
| `POST E/emergency-stops` | 明确 run／服务范围与原因；单调撤销版本，优先发布停止执行租约 |
| `GET E/reservations/{reservation_id}/drain-status` | `reclaim_after`、旧快照失效界限、token／在途窗口、仍未满足的回收条件 |
| `GET E/audit-events` | 按操作者、资源、动作、时间和 request_id 查询脱敏审计 |
| `GET/POST E/configuration-changes` | 为基线或拓扑版本创建发布变更请求，绑定目标版本、差异和依赖摘要；不借用虚假的实验 run |
| `POST E/configuration-changes/{change_id}:approve` | 审批精确目标版本和差异，记录审批身份；目标或依赖变化须重新校验 |
| `POST E/configuration-changes/{change_id}:publish` | 审批有效后创建发布任务，沿用编译、CAS、租约及回收规则 |

`publish_task.status=building|distributing|active|failed`；细步骤包括编译、存储校验、readiness、CAS 激活与装载观测。`active` 表示发布指针已激活；独立的 `rollout_status=converging|converged|degraded` 和覆盖率描述实例状态，未知实例不能算作已确认。目标失效或取消保存在 failure code，不把数据库已提交配置伪装为全部实例已装载。

回滚不直接把发布序列降回旧数字：创建新的 `release_sequence`，引用验证通过的历史内容或新编译产物。不得通过回滚复活已经物理复用桶的旧实验。结束时 logical completed 与 physical released 分开，必须等待最大旧快照签发时间、上下文执行期限、在途窗口及时间容差全部满足。

### 6.2 可信运行配置 API

```http

```

机器身份绑定 tenant／project／environment／service 及能力，连接使用 TLS，内部调用按组织要求采用 mTLS 和短期工作负载凭证。配置 URL 不依赖客户端任填 project/env/service 切换权限；凭证只允许一个绑定范围或明确列举范围。直接决策角色可以获取获授权依赖的规则投影；执行角色只能解析当前服务值。公开客户端不得调用全规则下载。

示例 `200` 返回服务投影 manifest；摘要和签名为示意值，不能用来测试验签：

```json

    "schema_version": 1, "project_id": "prj_shop", "environment_id": "env_prod", "service_id": "svc_rank",
```

`manifest_signature` 的 JWS payload 是 `data` 的 JCS 规范化字节，使用客户端预置信任的 key 与 ES256 算法白名单验证；未通过验签前不相信其中的路径和租约。manifest 自身必须被签名并与产物摘要、作用域、有效期绑定；不要只签 payload 却让路径／租约可被替换。不可变 artifact 内容不包含会随租约续期而改动的运行有效期，not_before／expires_at 属于签名 manifest；相同内容可签发新 manifest，但不能绕过已生效撤销。详细签名编码、JCS 与 hash 输入见 [SDK 协议](./03-SDK与分流协议.md)。示例有效期不是上线配置承诺，实际期限由租约和回收策略确定。

SDK 完成完整下载、摘要／签名、Schema 和依赖校验后原子装载，用 `POST /api/runtime/v1/snapshot-acks` 上报 `instance_id, config_revision, projection_id, status=loaded|rejected, loaded_at, sdk_version, error_code?`，幂等键由实例／配置／结果形成。ACK 证明该受控实例的装载事实，不保证业务执行成功。

`GET /api/runtime/v1/revocations/active` 提供短租约的撤销栅栏与强 ETag，撤销序号单调不降。SDK 缺少有效执行租约时按约定回退或拒绝实验处理，不能继续用长期缓存绕过停止。配置可以包含可公开业务值或受控资产引用，不能包含用户密码、机器密钥等 secret；签名提供完整性，不提供保密性。

## 7. 运行时批量决策

### 7.1 端点与信任边界

`POST /api/runtime/v1/evaluations:batch` 在一次业务决策中，针对一个固定随机化单元批量返回多个参数，可同时包含并行层中的多个实验。首版不在同一请求中混合多个用户。可使用有效配置的可信 SDK 本地决策，或由授权 BFF／服务调用远程决策；二者必须输出同一结构并遵守相同 hash、快照及事件契约。

普通浏览器和移动端只调用所属 BFF 的业务接口，BFF 从登录会话／可信匿名身份获得 `unit.id`，不能相信客户端任意冒用他人 ID。BFF 返回明确允许公开的最终参数值；不转发全量规则、私有服务参数、完整画像或通用机器凭证。用于公共客户端事件的受限凭证不能具有 `contexts:resolve` 或配置下载能力。

以下字段为服务端权威：scope、调用 service、当前配置、固定资格、unit 假名、run 与分组。请求中的参数 Key、资格引用与可选 config_revision 只是待授权和验证的选择，不能越权覆盖这些事实。

### 7.2 请求 Schema 与示例

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `request_id` | 是 | 本次逻辑评估的唯一随机 ID；网络重试保持，新的业务决策生成新 ID |
| `unit` | 是 | `{type:"user_id",id:"..."}`；首版只支持可信 user_id；后续单元类型必须先完成实验设计评审 |

```json
    "snapshot_id": "profile_4831_epoch_9", "eligibility_epoch": "elig_epoch_9", "proof_token": "opaque-trusted-proof"
```

身份服务把原始 ID 转为项目内稳定 `unit_key`，事件采用同一假名值 `unit.id_hash`。不把原始 ID写入通用日志。固定资格原子首次写入后包含当时缺失字段；不能在旧 snapshot 上补填后来出现的属性，以免破坏同桶互斥证明。可信引用 epoch 不匹配为 `409 ELIGIBILITY_EPOCH_MISMATCH`，不得偷偷新建资格覆盖旧周期。

服务端以 `(scope, caller_id, request_id)` 保留原决策及请求摘要，保留期不短于声明的重试窗口；同 ID 同请求重放同一 `decision_id/config_revision/assignments`，不能在重试时使用最新配置重算。同 ID 不同请求 `409 REQUEST_ID_REUSED`。配置和资格在一次评估开始时固定；批量中不得一部分用旧配置、一部分用新配置。

SDK `get`／本接口成功响应只证明查询与分配，不自动计曝光。处理前业务资格触发、实际执行／曝光和结果上报由各自事件定义；同一次决定多个参数不应因每次 getter 调用重复计样本。

### 7.4 重试与投影一致性

缓存重放不延长原 `expires_at`，不可把已过期 token 用于新执行。对过期的旧逻辑请求重试可以返回原始决策以便恢复关联，但需要新的业务决策时须显式创建新的 request_id；调用链不能静默自行重算。服务端给出重试窗口，客户端超窗不保证幂等重放，应先用内部关联记录恢复业务状态。

不允许通过仅请求本服务参数而改变其他相关层的随机结果。`business_scope` 由控制面登记完整业务决策范围和可参与服务，authority 按该范围构建完整分配，再将 parameter_keys 用作返回投影；服务权限不足不能通过任意 scope 字符串扩大。BFF 的权威决策构建完整、获授权的调用链上下文，再对各服务生成投影；本地直接决策服务只有在身份、hash 协议、配置 revision、资格 epoch／snapshot 均相同的情况下才能声称结果等价。

## 8. 跨服务上下文解析

`POST /api/runtime/v1/contexts:resolve` 消费已有决策，按当前服务权限返回所需值，不再次选组，不读取“最新”实验覆盖。网络载体使用单一 `X-Experiment-Context` opaque token 或约定的 gRPC metadata；MQ 将其放消息 envelope。入口剥离外部伪造载体，校验签名／记录、scope、目标 audience、有效期与撤销栅栏。

```json
{
  "decision_token": "opaque-execution-context-token",
  "parameter_keys": ["ranking.temperature"],
  "request_id": "resolve_request_rank_74a1"
}
```

调用身份是 `svc_rank`；不能凭请求体把自己改成另一个服务。resolve 只访问原 decision 的 business_scope，不允许扩展范围或给原范围外实验补分组。返回沿用第 7 节结构，保持 `decision_id/config_revision/run_id/variant_id` 不变，仅裁剪授权 `parameters` 和对应 assignments，并重建本响应的 `assignment_index`。token 可以是受签名封装的短字段或服务端上下文句柄，不要求业务解析 token 内部；平台不能依靠前端自行声明分组来生成上下文。

`CONTEXT_EXPIRED`、`CONTEXT_REVOKED`、`CONTEXT_SCOPE_MISMATCH` 或依赖 bundle 不可解析时不能调用 evaluate 悄悄补一份新组。按服务约定回退／拒绝，执行事件记录原决策及实际值。各服务参数的授权投影是只读解析，不保证模型和代码都已成功加载；需要整体一致的业务由编排层协调回退，不能把部分执行记为全部成功。

token 的执行有效期与事件验收期限分开。迟到曝光或业务事件携带旧 token 时，接收端查询已保存的决策、当时有效时间与采集策略；不会仅因“现在 token 已过期”拒绝合法历史事件。已过期 token 也不能证明一个发生在失效后的新处理合法，必须校验 `event_time`、服务身份、执行窗口及允许时钟误差。

上下文不在 URL、公开缓存 Key 或全量访问日志中传播；日志只记 decision_id 与脱敏摘要。响应缓存必须包含决定内容的版本／投影与分组因素，SSR 和 hydration 复用同一次决策，避免缓存把其他分组参数给当前用户。

## 9. 事件接收协议

### 9.1 类型与公共字段

`POST /api/runtime/v1/events:batch` 接收 SDK／BFF／业务服务的持久异步事件。配置查询不顺便上传曝光；只读参数多次查询不得增加主指标样本。事件语义与统计处理详见 [指标生产与分析](./04-指标生产与分析.md)。

| `event_type` | 产生者与含义 | 不能据此推断 |
| --- | --- | --- |
| `qualification` | 在实验处理之前发生的业务资格／机会触发；带冻结 `trigger_id` 和本次事实 `qualification_id`，用于预定分母 | 不能由处理后的点击或成功请求反推资格 |
| `assignment` | 可信决策服务或本地决策 SDK 为 run 记录随机分配；同一 decision 按 assignment 展开 | 分配成功不等于处理执行／曝光 |
| `execution` | 服务实际使用的 bundle、模型、值摘要和 fallback；可包含失败事实 | 实际执行不一定满足已定义的可见曝光 |
| `exposure` | 已满足该 run 预先定义的业务曝光点，标明触发／机会身份与实际处理 | 不以查询、到达层或所有 SDK getter 作为曝光 |
| `business` | 订单、点击等业务事实及更正；可不带 decision/run/variant | 客户端附带的组标签不是可信归因依据 |

`trigger_id` 是运行前冻结的机会／资格触发定义，`qualification_id` 是本次资格判定事实身份，二者互不替代；资格事实与随后 assignment 以明确关联字段连接。

公共 envelope 必填 `schema_version, event_id, event_type, event_time, producer_id, project_id, environment_id`；参与归因的事实必填 `unit:{type,id_hash}`，有业务请求时提供 `request_id`，无请求的可信 CDC／账本事件不伪造请求号；可关联时带 `decision_id, run_id, variant_id, config_revision, decision_token`。`received_at` 由接收端写入。字段中的 scope 必须与凭证绑定一致，producer 必须在该工作负载允许集合中；没有可信来源的 `id_hash` 必须由 BFF 身份通道重建。

assignment、execution、exposure 的 run／variant 从 token 或服务端保存的 decision 校验；payload 不得改写。同一 decision 含多个实验时，为每个被报告 run 提供明确的分配行，不能任取第一组。business 不强制提供实验标签；平台按相同 scope、随机化单元、可信 assignment 与冻结窗口进行 join。

```json
{
  "data": {
    "batch_id": "batch_events_1", "received_at": "2026-09-19T15:01:16.000Z",
    "results": [
      {"event_id": "evt_exec_74a1", "status": "accepted"},
```

正常返回 `202`。accepted 表示事件已写入持久接收日志／inbox，不能在仅进入进程内存后 ACK；不表示已完成归因或统计计算。duplicate 表示相同身份及正文已接收；rejected 带逐条 `code, field_path, retryable`。外层 JSON 或鉴权失败则整个请求返回 4xx；超大批次 413。服务不可用而无法持久接收时返回 503，重试保留原 event_id；若 ACK 在网络丢失，完整重传不会产生新事实。

传输去重键为 `(tenant,project,environment,producer_id,event_id)`。相同键不同正文进入冲突隔离并返回 `EVENT_ID_PAYLOAD_MISMATCH`，不能覆盖原记录。业务去重另使用 `(scope,source_system,source_event_id,source_version)`；订单重发不能仅换 event_id 就重复计收入。退款／调整采用独立 `adjustment_id` 与关联业务身份，不能把每次重试都算作新增扣减。事件时间超出允许范围、未知 Schema 或无法验证归属进入隔离，保留可审计原因。

逐项 rejected 仅对 `retryable=true` 条目保持原 ID 重试；修正内容后使用新的更正事件身份并关联原事件，不允许更换正文复用旧 ID。SDK 采用有界缓冲、退避、磁盘队列或组织标准采集代理，达到容量上限计丢失量并报警，不能无限占用业务内存或阻塞主链路。

## 10. 指标目录、分析计划与结果查询

指标版本和分析计划是固定运行契约。它们不能在看到结果后被原地修改为“更好看”的口径。首版计划、统计方法和数据质量约束由 [指标方案](./04-指标生产与分析.md) 定义，API 只引用受支持的版本化方法，不接受浏览器提交任意 SQL。

### 10.1 计划编写、校验与冻结

计划从草稿的 `analysis_plan_draft` 创建：通过 `PUT E/experiment-drafts/{draft_id}` 随其他内容保存，使用同一 If-Match；允许暂时不完整。`:validate` 检查计划并返回字段定位；`:submit` 必须通过全部计划检查，在创建实验 revision、run 和预留的同一事务中写入不可变 `analysis_plan_version` 及指标关联，再将 `analysis_plan_version_id` 绑定给 run。不存在“先提交运行、之后补分析计划”的生产路径。提交响应和 run 详情均返回这个 ID；若随后审批退回，新草稿包含可编辑副本，原计划不变。

| 字段 | 提交时约束 |
| --- | --- |
| `design` | 首版固定 `fixed_horizon`；序贯检验不接受仅靠字符串启用 |
| `randomization_unit, identity_namespace_id` | 必须匹配运行和可信身份策略；不能用事件数量替代随机化单位 |
| `population_spec` | ITT 或预注册处理前触发群体；冻结 trigger 定义、排除政策与资格依据；祖先条件由服务端绑定 |
| `enrollment_window` | 明确 `start_at < end_at`、UTC；启动延误不得自动平移／延长计划 |
| `outcome_window` | 每单元自首次分配起固定观察 W，`duration_seconds > 0`；暂停后已入组观察继续 |
| `lateness_policy` | 明确传输迟到 L 与每个指标的业务更正 H；不能用 watermark 替代源完整性证明 |
| `metrics` | 恰好一个主指标，显式必需护栏，可另有次要／诊断指标；每项固定 metric_version_id、方向、假设及方法 |
| `alpha, power, mde, mde_scale` | 有限数；`0<alpha<1`、`0<power<1`、`mde>0`，MDE 说明绝对／相对；不同于流量 bps |
| `sample_plan` | 各组目标独立随机化单元数、历史基线与方差依据、计算器版本；与实际权重、指标分布和比较族一致 |
| `comparison_family` | 正式假设集合、唯一 control、处理对对照比较、多重校正与区间政策；不隐式追加全部组间比较 |
| `stopping_rule, guardrail_policy` | 固定结束规则、样本不足行为、预授权安全止损与提前停止后的结论限制 |
| `allocation_schedule, quality_policy_version_id` | 冻结允许的流量节奏及质量门禁；扩量也必须符合原计划，不得为了显著性事后改变节奏 |

H=0 表示这些示例指标没有额外业务更正等待期，不代表传输不迟到；净收入等指标可按固定版本定义独立 H。成熟时间与 `enrollment_end + W + H + L`、源完整性共同判断。计划引用的 trigger、质量和止损政策也必须版本化；运行受众／祖先路径、分组及权重由提交事务补齐快照，前端不能声明一份与实际实验不同的研究设计。若计划字段需改变，复制为下一 run 草稿并重新审核。

### 10.2 目录与结果 API


| 方法与路径 | 请求／返回重点 |
| --- | --- |
| `GET/POST P/metrics` | 指标目录身份、名称、负责人、业务说明 |
| `GET/POST P/metrics/{metric_id}/versions` | 事件、实体、分子／分母、窗口、单位、去重及调整语义；新版本不可变 |
| `GET R/analysis-plan` | run 冻结计划：主／次／护栏指标版本、触发、单位、窗口、比较、MDE、检验与校正 |
| `GET R/analysis-runs` | 分析批次，按 `analysis_run_id` 返回数据截止、水位、状态及质量 |
| `POST R/analysis-jobs` | 申请计算／迟到重算；传 cutoff、原因和受支持模式，异步返回 `analysis_job_id` |
| `GET E/analysis-jobs/{analysis_job_id}` | 调度进度和失败原因；完成时关联 analysis_run_id |
| `GET E/analysis-runs/{analysis_run_id}` | 冻结 `analysis_plan_version_id, data_snapshot_id, cutoff, code_version` 和结果元信息 |
| `GET E/analysis-runs/{analysis_run_id}/metrics` | 分组样本、指标估计、绝对／相对差、置信区间、校正检验与结论状态 |
| `GET E/analysis-runs/{analysis_run_id}/quality` | SRM、丢失、归因失败、迟到、回退、成熟窗口等质量检查 |
| `POST E/analysis-runs/{analysis_run_id}/exports` | 异步导出授权聚合报告；不提供任意用户明细导出 |

`analysis_run_id` 是分析计算身份，不能和实验 `run_id` 或调度 `analysis_job_id` 混用。重算生成新的 analysis_run_id，并用 `supersedes_analysis_run_id` 关联被更正结果；旧报告只读保留，不覆盖数值。预览与最终结果必须显式 `result_status=invalid|insufficient|provisional|final`，任务运行成功不代表统计结论有效；同时存在多个阻断时以 `invalid > insufficient > provisional > final` 判定展示状态，并通过 `quality_findings[]` 保留各条原因。

```json
{
  "data": {
    "analysis_run_id": "arun_feed_20260920_1", "run_id": "run_feed_1",
    "analysis_plan_version_id": "apv_feed_1", "data_snapshot_id": "ds_20260920_1",
    "cutoff": "2026-09-20T00:00:00.000Z", "code_version": "analysis_code_1",
    "result_status": "insufficient", "quality_status": "pending", "quality_findings": [],
    "metrics": [
      {
        "metric_version_id": "mv_click_rate_1", "variant_id": "var_treatment", "control_variant_id": "var_control",

        "confidence_interval": null, "adjusted_p_value": null, "conclusion": "insufficient_data"
```

## 11. 错误协议、限流与可观测性

错误媒体类型采用 `application/problem+json`，字段兼容 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)，使用扩展字段携带稳定业务码、重试属性和表单定位。成功响应有 data envelope，错误体不再多包一层 `error`。

```http
HTTP/1.1 422 Unprocessable Content
Content-Type: application/problem+json
```

```json
{
  "type": "urn:explab:problem:validation-failed",
  "title": "实验配置校验失败", "status": 422,
  "detail": "实验组参数源码包含重复字段，草稿原文已保留。",
  "instance": "urn:explab:request:req_validate_8", "code": "VALIDATION_FAILED",
  "request_id": "req_validate_8", "retryable": false,
  "errors": [
    {
      "code": "JSON_DUPLICATE_KEY", "field_path": "/variants/1/parameters_source",
      "section": "variants", "variant_id": "var_treatment", "parameter_key": "ranking.temperature",
      "source_pointer": "/ranking.temperature", "line": 4, "column": 3,
      "message": "同一对象重复声明 ranking.temperature"
    }
  ]
}
```

`field_path` 是请求外层 JSON 的 Pointer；`source_pointer` 定位字符串内解析对象，无法解析时可缺省并依靠行列定位。Pointer 转义遵循 [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901.html)，`/` 转义为 `~1`、`~` 转义为 `~0`；Key 中的点是普通字符，不能按点拆路径。行列按源码中的 Unicode 标量计数并从 1 开始，前端负责转换为编辑器的 UTF-16 偏移。错误不回显完整原文、画像、token 或秘密参数。

| HTTP | 示例 code | 客户端处理 |
| --- | --- | --- |
| 400 | `MALFORMED_JSON / INVALID_CURSOR` | 外层请求不合法，修正后新请求；草稿内错误源码不属于此项 |
| 401 | `UNAUTHENTICATED` | 凭证失效；刷新一次，保留幂等身份 |
| 403 | `FORBIDDEN / CONTEXT_SCOPE_MISMATCH` | 不自动切换其他服务身份重试 |
| 404 | `RESOURCE_NOT_FOUND` | 对象不存在或不可见；不得自动创建同名资源替代 |
| 409 | `ALLOCATION_CONFLICT / PLAN_STALE / RELEASE_IN_PROGRESS / REQUEST_ID_REUSED` | 返回安全的冲突范围、当前依赖版本和建议操作；重读／重校验；只有明确暂态码可退避重试 |
| 410 | `CONTEXT_EXPIRED / CONTEXT_REVOKED` | 停止用该上下文执行；按既定回退规则处理，历史事件单独校验 |
| 412 | `REVISION_MISMATCH` | 暂停自动保存，保留本地正文；获取新 ETag 后人工合并或另存新稿 |
| 413 | `PAYLOAD_TOO_LARGE` | 拆小事件批次或按上限缩减源码；不得静默截断 |
| 422 | `VALIDATION_FAILED / PARAMETER_NOT_ACTIVE / ANALYSIS_PLAN_INVALID` | 定位具体字段修正；不原样自动重试 |
| 428 | `PRECONDITION_REQUIRED` | 先读资源 ETag，再发条件更新 |
| 429 | `RATE_LIMITED` | 按 Retry-After 与调用方预算退避，重试身份不变 |
| 500/503 | `INTERNAL_ERROR / DECISION_UNAVAILABLE / INGEST_UNAVAILABLE` | 有界重试；请求可能已提交，应以幂等身份恢复，不能假定从未执行 |

`GET /api/admin/v1/capabilities` 和 `GET /api/runtime/v1/capabilities` 返回当前身份范围支持的 API／事件／配置 Schema 版本、请求大小、批次、文本深度、重试和租约上限。它们只公开契约限制，不暴露实例拓扑或凭证。已知协议不兼容要在装载／请求开始前拒绝，不让 SDK 在字段未知时猜测桶分配含义。

按租户、项目、环境、服务和路由能力限流，管理大查询、配置下载、决策、事件分别计额；不能因一个导出任务阻塞线上决策。服务端透传并校验追踪上下文，日志关联 `request_id/decision_id/publish_task_id/analysis_run_id`，记录延迟、结果码与脱敏 scope；严禁以完整 payload 代替结构化审计。

## 12. 兼容策略与接口验收

`/v1` 内只做向后兼容的字段增加；改变类型、缺省语义、单元身份、分流算法、event 去重或枚举含义需新版本／显式能力协商。SDK 遇到不能理解的运行关键枚举或 hash_protocol 应拒绝产物；管理展示客户端可以把新的展示状态显示为未知，但不能擅自执行状态命令。旧 camelCase/localStorage 数据只在迁移层翻译，不让一个生产端点同时接受两个语义不一致的字段。

接口验收至少包含以下可观察结果：

1. 两个编辑者持同一 ETag 保存，只有一个成功；另一个 412 且原文不丢。无效组内 JSON 可保存，提交必须返回准确定位。
2. 相同 source_draft_id 与幂等键重复提交只生成一个 run／预留；审核退回获得新 draft_id，旧提交重试仍返回旧 run。
3. 多个请求并发抢最后可用桶，事务串行验证无双占；参数激活、拆层、子域创建与实验提交同时发生也保持完整分区。
4. 受众预览后祖先或占用改变，提交重校验；unknown 证明不放行相交桶；任意前端画像不能更改固定资格。
5. 审批后依赖摘要改变，启动拒绝旧批准；发布受理不伪称实例生效；结束后 draining 未满足时相交桶不可复用。
6. 一次评估多个层返回 assignments 数组；同 request_id 重试不换配置；resolve 在不同服务仅投影授权参数且不换组。
7. 短 token 到期后不能继续执行；允许窗口内合法历史曝光仍可核验接收；前端伪造 run／variant 被拒绝或隔离。
8. accepted ACK 只发生在持久化后；网络丢 ACK 重试不重复计数；相同 event_id 不同 payload、重复订单和独立退款各按协议处理。
9. 无业务事件的合格分配单元保留统计分母；零样本返回 null／insufficient_data；迟到重算产生新 analysis_run_id，历史结果不覆盖。
10. 跨租户、项目、环境及服务投影的直接对象访问、游标复用和配置缓存均无法越权；公开客户端无法下载规则或机器凭证。

以上是待实现服务的契约验收清单，不表示这些接口已经通过测试。当前仓库的前端构建与测试不能替代数据库并发、运行鉴权、跨语言 SDK 或真实采集链路验证。
