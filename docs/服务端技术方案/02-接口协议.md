# 服务端接口协议

版本：设计基线 v1.3｜日期：2026-09-23｜对照原型：v23。

本文为待实施契约；当前仓库仅有前端原型，HTTP、鉴权、事务、签名和事件接收均未实现。原型依据 [README](../../README.md) 与[现有技术方案](../平台文档/02-技术方案.md)，授权规范见 [Namespace 与权限设计](./05-Namespace与权限设计.md)。

## 1. 范围、身份与版本

### 1.1 资源作用域

单企业、单部署、多 Namespace。原项目直接改称 Namespace，不新增一层实体；已有 opaque ID 保持原值。路径缩写 `N = /api/admin/v1/namespaces/{namespace_id}`、`E = N/environments/{environment_id}`；请求必须展开。运行与数据 `scope = (namespace_id, environment_id)`。

| 作用域 | 资源 | 边界 |
| --- | --- | --- |
| deployment | 全局 principal、用户／机器身份、角色模板、Namespace 目录 | 同一身份可加入多个 Namespace；角色模板由平台管理；组授权首期延期 |
| namespace | 成员、授权绑定；服务、参数、标签、画像属性、受众、指标及其版本 | 资源／配置／授权隔离；Key 在 Namespace 内唯一；不能跨 Namespace 引用或授权 |
| environment | 服务接入、参数归层、基线、域层、草稿／实验／运行、桶预留、审批／发布、分析结果 | 开发／测试／生产分别授权；账本、指针、运行状态不共用 |

Namespace 隔离不保证用户流量互斥或因果隔离。同一首页需联合控参的团队放在同一 Namespace，通过资源授权协作；不能靠跨 Namespace 共享引用拼接联合实验。

参数定义在 Namespace；根路由层存在该参数的归层记录即该环境 active，否则 pending，不另存环境状态表。注册不选层、不扩张拓扑；首次激活须在同一事务完成所有受影响域的归属。目录显示归层状态时必须指定 `environment_id`。

```mermaid
flowchart LR
  A[可信 OIDC / 工作负载身份] --> B[有效 namespace_member]
  B --> C[解析资源真实归属与环境]
  C --> D[本对象动作 + 全部依赖权限]
  D --> E[业务校验 / 事务内再校验]
  E --> F[写入 + 审计 + outbox]
```

| 授权规则 | API 必须执行 |
| --- | --- |
| 准入 | 服务端从可信凭证解析全局 principal；Namespace 内请求先验证有效 `namespace_member`，human/machine 均需显式成员及直接授权 |
| 资源动作 | RBAC 角色动作集与资源绑定；沿归属树继承，引用不继承；allow 并集、默认拒绝，无 deny |
| 创建 | 在真实父资源检查创建／manage 动作，有效绑定引用须验证 Namespace、环境、服务归属；原子写入真实业务资源；未完成草稿的固定显式绑定例外见 §5.1 |
| 环境限定 | 只授指定环境中的操作；不能据此修改 Namespace 目录定义。标签、owner 不授权限 |
| 返回 | 无权知道是否存在返回 `404`；可见对象缺动作返回 `403`；列表按对象 read 权限过滤，`namespace.read` 不代表全目录可见 |
| 权限变化 | 成员／绑定变更、`policy_revision` 递增与审计同事务；写提交前再次校验，不能让撤权与写入竞态穿透 |
| 撤权效果 | 阻止新请求；不自动停止已发布实验。运行停止、配置撤销仍走发布及租约协议 |

### 1.2 基础类型与标识

| 字段／类型 | 协议定义 |
| --- | --- |
| JSON 字段 | `snake_case`；`Content-Type: application/json`；UTF-8；未知请求字段默认拒绝，客户端忽略未知响应字段 |
| `*_id` | opaque string，不解析前缀、位数、顺序或业务含义；示例前缀仅便于阅读；路径段按 URI 规则编码 |
| `revision`、`experiment_revision`、`allocation_revision` | 从 1 开始的单调整数；分别为资源乐观版本、不可变实验内容版本与同 run 分配映射版本，不能混用 |
| `config_revision` | 不可变配置产物标识字符串；不按字典序比较；发布顺序用独立的 `release_sequence` 整数 |
| 时间点 | RFC 3339 UTC，例 `2026-09-19T15:00:00.000Z`；不传本地无时区时间 |
| 日期 | 管理信息的 `expected_end_date` 为 `YYYY-MM-DD`；按环境继承的 Namespace `timezone` 计算提醒，不代表 UTC 时间点 |
| 比例 | `*_bps` 为整数 `0..10000`，1 bps = 0.01%；分组权重必须大于 0，全部组之和等于 10000 |
| 桶段 | `{ "start": 0, "end": 1000 }`，整数、左闭右开，`0 <= start < end <= 10000`；返回值已排序、合并相邻段且无重复 |
| 金额与精确小数 | 用带单位的十进制字符串或明确整数最小单位；不得依赖 JSON 浮点数表示财务精度 |
| 可空字段 | 未提供表示不修改；显式 `null` 仅用于 Schema 声明可清空的字段；不把空串、缺失与 null 混为一谈 |

| 运行身份／变化 | 契约 |
| --- | --- |
| experiment_id | 长期业务身份 |
| run_id | 固定受众、单位、分组、参数与指标方案的一次运行 |
| experiment_revision | 审批／编译绑定的不可变内容 |
| 权重／值／受众／统计变化 | 新 run |
| 同 run 扩量 | 保留旧桶、原分组和固定方案，只新增 allocation_revision |
| 暂停／恢复 | 同 run；completed 不再开启 |

v1.3 控制库固定 30 张表，清单见 [数据库设计](./01-数据库设计.md)。下列协议身份保留，但不各自对应独立表：

| 逻辑身份／操作 | 持久化位置 |
| --- | --- |
| experiment_revision、variant_id、analysis_plan_version_id | `experiment_run` 及 contract_snapshot 中的不可变运行契约；生命周期分字段维护 |
| topology_revision、baseline_version_id、审批请求 | `change_request` 的冻结目标和依赖；生效配置由 `release` 快照回溯 |
| publish_task_id、release_id、config_revision | `release` 的发布身份、状态及不可变配置元数据；任务 ID 定位同一发布记录 |
| projection_id、parameter_bundle_id | release 对象产物内的固定索引和独立授权文件 |
| analysis_run_id、data_snapshot_id | `analysis_job` 的冻结输入／结果元信息；结果正文在对象存储 |

核心归属用真实复合 FK；快照引用在受控事务完整校验作用域、存在性和权限，冻结后不再用目录当前值重建历史。

### 1.3 成功响应、分页与条件读取

单资源返回 `{"data": {...}, "meta": {"request_id": "..."}}`；集合返回 `data` 数组及 `page`。创建成功为 `201` 并返回 `Location`；异步命令为 `202` 并返回任务地址；查询和同步更新为 `200`。HTTP `request_id` 为服务端追踪号，独立于运行评估请求体中的业务重试 `request_id`。

```json
{
  "data": [
    {"experiment_id": "exp_feed", "name": "推荐策略实验", "current_run_id": "run_feed_1", "state": "running"}
  ],
  "page": {"limit": 50, "next_cursor": "cur_opaque", "has_more": true, "read_snapshot_id": "read_opaque"},
  "meta": {"request_id": "req_admin_1"}
}
```

| 集合／条件请求 | 约束 |
| --- | --- |
| 分页 | limit 默认50、最大200；opaque cursor 绑定调用者、授权范围／policy_revision、Namespace／环境、过滤／排序及一致读取位置 |
| 排序 | created_at desc, id desc；不接受任意 SQL 排序，默认不返回精确总数 |
| 游标失效 | 过滤变化清空；授权变化／过期返回 409 CURSOR_EXPIRED，从首屏重读，不接续其他集合 |
| 时效 | 每页重检成员及授权有效期；policy_revision 相同也不能沿用已过期绑定 |

编辑资源／拓扑返回强 ETag；写入原样带 If-Match，缺失428、过期412。If-None-Match 未变返回无正文304。ETag 不由客户端拼接；带 ETag 的 GET 仅用 X-Request-ID 追踪，不在正文加入变化的 meta.request_id。条件请求遵循 [RFC 9110 §13](https://www.rfc-editor.org/rfc/rfc9110.html#section-13)。

### 1.4 幂等、并发与重试

创建及命令类 `POST` 必须带 `Idempotency-Key`；纯查询的 `:check`、`:preview`、`:validate`、模拟接口除外。部署、Namespace、环境命令统一写 idempotency_record：唯一键为 `(scope_key, principal_id, operation, idempotency_key)`；principal 来自可信调用者，幂等键来自请求头，operation 为规范化 HTTP method + canonical_path。scope_key 由服务端按固定 deployment 值或真实 N/E ID 生成非空规范编码，并与 scope_kind、可空 N/E 强约束一致；客户端不得指定。服务端存储请求摘要、执行状态和原始响应。外层 JSON 按稳定规范化计算摘要；草稿源码字符串保留原文字节含义，不能先解析丢失重复字段或格式。

- 同键同内容：返回同一资源／任务和原响应，响应头 `Idempotent-Replayed: true`。重放前重检当前可见性与调用权限，再读原结果；不因原 `If-Match` 已旧而再次执行。
- 同键不同内容：`409 IDEMPOTENCY_KEY_REUSED`；同键仍在执行：`409 IDEMPOTENCY_IN_PROGRESS`，按 `Retry-After` 以原键重试。
- 幂等记录的最低保留期为 24 小时，并在响应声明 `Idempotency-Key-Expires-At`；客户端不得复用旧键。草稿提交另有持久唯一关系 `source_draft_id → experiment_id/run_id`，不能只依赖短期缓存防重。
- 版本检查、占桶、状态更新、审批绑定、审计和 outbox 在同一数据库事务完成。管理鉴权首期直查当前状态，低频环境写在环境锁内串行；成员、角色等变更与业务写遵循统一锁栅栏，事务内不做网络调用。`preview_id` 与前端通过提示不持有数据库锁，不构成流量保留。
- `429`、`503`、网络超时：在整体截止时间内按 `Retry-After` 或指数退避加随机抖动重试，写请求保留同一键和内容。`409` 领域冲突、`412`、`422` 需要重读或修正，不能无限原样重试。`401` 仅允许刷新凭证后重试一次。

### 1.5 端点动作与联合校验

动作码以 [权限设计](./05-Namespace与权限设计.md) 为唯一字典。表中“读／写”指以下各节同资源端点；创建在真实父资源检查动作，已有对象在自身检查。资源 read 不自动包含 use、edit、approve、publish 或 export。

| 端点族／操作 | 动作与额外条件 |
| --- | --- |
| 服务资料、标签、接入配置／验证／观测 | `service.read`／`service.manage`；机器凭据生命周期另需 `iam.credentials.manage` |
| 参数定义／版本／标签 | `parameter.read`／`parameter.manage`；Namespace 目录写不能使用环境限定授权 |
| 参数激活／转层 | `parameter.assign` + 目标／来源层 `layer.manage` + 全部参数 read/use；改变资格时检查全部受众 read/use，所有受影响域全量校验 |
| 画像属性、受众、指标目录及版本 | 对应 `profile_attribute.read/manage`、`audience.read/manage`、`metric.read/manage` |
| 受众检查／引用查询 | `audience.read` + 用到的 `profile_attribute.read`；关联实验／域只展示有对应 read 的对象 |
| 域／层创建与管理 | 父范围及目标 `domain.manage/layer.manage`；子域另需父层 layer.use；全部继承参数、祖先及新受众 read/use |
| 拓扑、预留／归层／流量预览 | 目标 `domain.read/layer.read` 与引用 read；申请使用另需 `layer.use`，不可见冲突仅给脱敏阻断 |
| 草稿创建／读取／保存／校验／归档 | `experiment.create/read/edit`；复制还需源 experiment.read；未完成草稿规则见 §5.1 |
| 提交实验 | 新实验在目标层同时重检 `experiment.create` 与 `experiment.submit`；已有实验在实验对象检查 `experiment.submit`，再 AND `layer.use` + 每个参数 `parameter.read/use` + 受众 `audience.read/use` + 指标 `metric.read/use`；读取草稿需 experiment.read，可见画像依赖需 profile_attribute.read |
| 审批／驳回 | `experiment.approve` + 实验及全部依赖可读 + 职责策略；无需 experiment.edit |
| 启动／恢复／扩量发布 | `experiment.publish` + 当前全部依赖 read/use + 有效审批／状态；扩量创建另需 experiment.edit/submit |
| 暂停／结束／紧急停止 | `experiment.stop`，逐个校验目标 run；紧急停止不授其他发布能力 |
| 基线／拓扑变更申请、审批、发布 | 基线申请／发布用 baseline.publish + 参数 read/use；拓扑申请用 domain.manage/layer.manage，发布用 topology.publish + 全部改变域／层 manage、承载层 use 及依赖 read/use；审批 configuration.approve + 全依赖 read |
| 发布历史／任务／排空状态／重试 | `release.read`；重试额外重检原命令动作、依赖与审批 |
| 发布回滚 | `release.rollback` + 目标内容对应 publish 动作 + 依赖／审批／回收栅栏 |
| 模拟、强制分组、详细分流诊断 | `runtime.debug` + 所有展示对象 read；仅沙箱，不写生产资格／曝光 |
| 审计查询 | `audit.read`；按 Namespace／环境／资源范围过滤，字段脱敏 |
| 分析计划／批次／质量／指标结果 | `result.read` + 所含 `metric.read`；多实验报告逐个授权 |
| 计算／重算、导出 | `analysis.execute`／`result.export`，并满足 result.read、metric.read；后台执行及下载前重检 |
| 运行评估、上下文、配置、事件 | `runtime.evaluate`、`runtime.context.resolve`、`runtime.config.read`、`event.ingest`；按可信机器的 Namespace／环境／服务与参数投影限制 |

引用关系不传播权限。实验 read/edit 不能自动读取或使用其他团队的参数；发布按钮可用也不能省略依赖校验。授权服务、业务写入与审计使用同一策略版本；提交前若 policy_revision 已变，重新决策或返回 `409 POLICY_CHANGED`。授权撤回后的幂等重放、任务执行、下载均重查当前状态。首期不实现管理权限 allow 缓存或跨 Namespace 缓存失效服务；policy_revision 仍用于审计、游标和并发校验。

## 2. Namespace 与目录 API

### 2.0 成员、角色与资源授权

平台端全局 principal 目录按需查询；Namespace 成员和直接绑定按本 Namespace 分页。平台身份治理能力不能从 Namespace 角色推导。角色动作与凭证 allowed_actions 数组均由版本化代码动作目录校验，不另建 permission／role_permission 表。

| 方法与路径 | 动作／请求重点 |
| --- | --- |
| `GET /api/admin/v1/namespaces` | 仅有效成员且有 `namespace.read` 的 Namespace；不返回其他空间名称或数量 |
| `POST /api/admin/v1/namespaces` | 部署根上的 `namespace.create`；`namespace_key,name,timezone,initial_admin_principal_id`；原子创建空间、初始成员及管理员绑定 |
| `GET/PATCH N` | GET 需 `namespace.read`；PATCH 需 `namespace.manage`，`If-Match`；不改既有 namespace_id |
| `GET/POST N/members`、`PATCH N/members/{principal_id}` | `namespace.members.manage`；显式维护成员状态／有效期；新增成员不自动授资源 read |
| `GET N/roles` | `iam.bindings.manage`；仅返回可委派平台模板及 `role_id,name,actions,delegable`；Namespace 管理员不能改模板 |
| `GET/POST /api/admin/v1/roles`、`PATCH /api/admin/v1/roles/{role_id}` | 部署根上的 `iam.roles.manage`；模板变更使受影响 Namespace 的 policy_revision 递增 |
| `GET/POST N/role-bindings`、`DELETE N/role-bindings/{binding_id}` | `iam.bindings.manage`；操作者范围包含目标、角色可委派、目标为有效成员；不能自提权或改平台角色 |
| `POST N/permissions:check` | 默认仅查自身；批量 `checks:[{action,scope,environment_id?}]`；environment_id 为本次操作上下文；返回 allowed 与 policy_revision，不代表预授权或锁 |
| `GET N/effective-permissions` | 自身有效动作及授权资源范围；查他人须 `iam.bindings.manage` 且目标在可管理范围；无权对象不展开 |

绑定的 `scope.resource_type + resource_id` 仅为协议选择器。服务端按封闭类型解析真实业务表，再写 role_binding 中恰一个对应类型的 FK；部署范围没有业务目标。继承沿业务归属计算，不建 auth_resource 或复制父树。`scope.target_environment_id` 定位资源自身环境；顶层 `environment_filter_id` 仅限定授权使用环境，可空，不能替代目标环境或跨 Namespace。两者均有值时必须相同。Namespace 目录目标不带 target_environment_id，可附 filter 满足指定环境的 read/use，仍不能编辑目录定义。

首期 `subject.type` 只接受 `principal`（human/machine）；`group` 返回 `422 UNSUPPORTED_SUBJECT_TYPE`，不转成个人身份。全局组、组成员及组绑定作为后续扩展；`/api/admin/v1/groups` 不在首期能力清单，调用返回统一未实现路由响应。

授权变更条件全部为 AND：有效成员 + `iam.bindings.manage` + 可委派角色 + 被授动作不超出操作者的可委派动作 + 操作者可管理范围包含目标范围 + 目标成员有效。主体必须是有效 principal；Namespace 绑定还要求该主体是有效成员，退出后立即失效，不自动添加成员。部署绑定不伪造 Namespace 成员。首次 Namespace 创建由受控平台流程原子建立成员与首个管理员，不能走“未入空间先自授管理员”。

**加入成员**：`POST /api/admin/v1/namespaces/prj_shop/members`，带 `Idempotency-Key`。

```json
{
  "principal_id": "usr_rank_editor",
  "status": "active",
  "expires_at": null
}
```

**绑定环境内实验编辑能力**：`POST /api/admin/v1/namespaces/prj_shop/role-bindings`，带 `Idempotency-Key`。角色动作和可委派范围由平台模板确定。

```json
{
  "role_id": "role_experiment_editor",
  "subject": {"type": "principal", "id": "usr_rank_editor"},
  "scope": {"resource_type": "layer", "resource_id": "lyr_rank", "target_environment_id": "env_prod"},
  "environment_filter_id": "env_prod",
  "expires_at": null
}
```

```json
{
  "data": {
```

## 4. 拓扑、归层与流量 API

| 方法与路径 | 核心行为 |
| --- | --- |
| `GET E/topology` | 按 `domain.read/layer.read/parameter.read` 投影，返回 topology_revision、ETag；隐藏资源不泄露名称、ID或值 |
| `GET E/layers/{layer_id}/reservations` | 桶段、预留状态、所有者及受众证明摘要；已逻辑结束但 draining 的占用仍返回 |
| `POST E/parameters/{parameter_id}/activation-plans` | 返回全部受影响域、候选归属、阻断项、依赖版本；不修改状态 |
| `POST E/parameters/{parameter_id}:activate` | 提交每个受影响域唯一归属；锁定相关域层账本，原子激活，不能部分成功 |
| `POST E/domains/{domain_id}/layers` | 新建层，可空层或合法转移参数；同域完整分区、来源非空保护与依赖检查 |
| `POST E/layers/{layer_id}/child-domains` | 创建子域并原子创建初始参数层；自动承接父层全部参数 |
| `PATCH E/domains/{domain_id}/management` / `PATCH E/layers/{layer_id}/management` | 只改负责人、期限和日期，`If-Match`；到期不触发实验终止或回收 |
| `POST E/allocation:preview` | 计算有效受众、冲突与自动组合桶段，不保留桶 |
| `POST E/traffic:simulate` | 完整递归模拟；测试身份和画像只能进入沙箱，不写生产固定资格、曝光或分析数据 |

UI 可用匿名“含无权依赖”提示不完整视图；后台始终校验全量拓扑，不能用可见参数集裁剪继承范围。缺少操作所需依赖权限时拒绝变更；不能靠隐藏资源绕过约束。

根域范围由根路由层参数映射决定，子域范围由父层完整参数推导，不另存 domain_parameter。根域只允许一个全参数路由层且不承载实验；域层交替嵌套，域深度最大 16。同域层集合恰好划分继承参数范围，空层可保存但不得承载实验或子域。非重叠域及其后代保持单路径；非重叠分支不会隔离祖先的其他并行层。所有命令在数据库事务重校验这些不变量，不能让前端自行拼装可写拓扑树。每次合法拓扑修改同步生成 change_request 完整不可变快照，递增 environment.topology_revision 并更新 workspace_topology_change_id；仅治理元数据修改也记录 metadata_only，不重随机化。

`child-domains` 接收 `name, mode, traffic_bps, audience_version_id?, management`，不接收初始 A/B 两层或任意删减的继承参数。`management` 为 `owner_id, lifetime=long_term|temporary, expected_end_date`；长期日期必须 null，临时必须有效日期，可为过去日期。初始层复制一次管理信息，后续独立维护。

plan_id 绑定 topology_revision、参数定义与层账本版本。activate 传 plan_id、assignments:[{domain_id,layer_id}]、If-Match；过期409 PLAN_STALE，不部分激活。根参数归层转移在同一事务更新归属，不得删除根映射把 active 退回 pending；存在子域、未结束 run 或 draining 引用时，父层参数集合不得任意改变。

### 5.3 实验列表与固定受众引用

`GET E/experiments` 支持 `q`、重复 `state`、重复 `service_id`、`owner_id`、`owned_by_me`、`layer_id`、`audience_version_id`、`audience_ref_mode=direct|ancestor|direct_or_ancestor`。默认受众模式为 `direct_or_ancestor`，引用来源按每个 run 冻结的受众与祖先版本计算，不能用今天已改变的拓扑重解释历史 run。多个独立筛选取交集，多 service 候选为任意匹配。

```http
GET /api/admin/v1/namespaces/prj_shop/environments/env_prod/experiments?audience_version_id=audv_cn_1&audience_ref_mode=direct_or_ancestor&state=running&service_id=svc_rank&limit=50
```

返回可包含 `matching_runs:[{run_id,reference_kind,via_domain_ids}]`，解释直接引用还是祖先继承。同一实验多次运行可引用不同版本，列表去重实验身份但保留匹配 run；未知或无权受众 ID 返回空集合，不偷偷撤掉筛选。该接口表示配置引用，不表示实际入组或曝光。画像属性入口先列使用该属性版本的受众版本，再逐版本使用此筛选。

详情使用 `GET E/experiments/{experiment_id}`；历史运行使用 `GET E/experiments/{experiment_id}/runs`；固定内容使用 `GET E/experiments/{experiment_id}/revisions/{experiment_revision}`，通过唯一的 experiment_run 序号读取 contract_snapshot；运行事实使用 `GET E/experiments/{experiment_id}/runs/{run_id}`。响应同时给出业务状态、审批、发布、有效区间和预留状态，不用单一“已上线”掩盖不同事实。

### 5.4 审核与状态命令

以下以 `R = E/experiments/{experiment_id}/runs/{run_id}` 缩写路径。命令统一携带 `If-Match`、`Idempotency-Key`、`reason`，服务端执行权限及状态检查。实验、扩量、拓扑和基线统一使用 change_request，按 kind 校验真实目标 FK 与冻结 target_snapshot；decisions 在行锁/CAS 下追加，同一 reviewer 不重复计票、旧决定不可修改，审批身份及审计同事务校验写入。

| 方法与路径 | 前置条件 | 结果 |
| --- | --- | --- |
| `POST R:approve` | `review`；精确 `experiment_revision + plan_digest + dependency_digest`；审批人符合职责策略 | 冻结批准记录，`approval_status=approved`；仍不开始处理 |
| `POST R:reject` | `review`，无已生效启动 | run 变 `completed`，`completion_reason=review_rejected`，返回新的可编辑 `draft_id` |
| `POST R:start` | `review` 且审批有效、预留有效、服务就绪 | 创建发布任务，目标 running；运行前不返回实验值 |
| `POST R:pause` | `running` 或已受理启动需由发布协调器串行处理 | 目标 paused，保留桶和分组，发布停止处理配置 |
| `POST R:resume` | `paused`，依赖仍有效、参数及分组契约未改 | 目标 running；沿用同 run 和原分组 |
| `POST R:complete` | `running/paused`，或显式取消未激活的 review | 目标 completed，停止新处理；预留进入 draining 或满足证明后直接释放 |
| `POST R/expansions:preview` | 原 run 合约未改；新 `traffic_bps` 严格增加 | 计算附加桶与新 allocation_revision，不保留 |
| `POST R/expansions` | 带原 allocation_revision、预览依赖和审批需求 | 创建同 run 新不可变 allocation_revision，保留 experiment_revision、旧桶、分组与 salt；审批发布后生效 |

`:reject` 不能把原 submitted 草稿改回可写，旧 run 不复活。只有能证明从未发布、未签发 token 的审核预留才直接 released；其他情况走回收栅栏。扩量审批绑定 `run_id + allocation_revision + allocation_digest + dependency_digest`，不改已批准的实验内容版本；扩量不修改既有 variant 区间映射；不能为了凑新的总体占比把旧用户重新分组。缩量、组权重／值／受众／分析计划变化必须新 run；第一期对存在冲突的替换 run，要等原 run 排空后才能取得相交预留，不默认给替换实验绕过账本。

状态命令返回示例：

```json
{
  "data": {
    "run_id": "run_feed_1", "state": "running", "desired_state": "paused",
    "publish_task_id": "pub_pause_1", "publication_status": "building",
    "reservation_state": "reserved", "all_instances_effective": false
  },
  "meta": {"request_id": "req_pause_1"}
}
```

| 状态事实 | 含义 |
| --- | --- |
| state／desired_state | 最近激活状态／发布目标；202只表示受理 |
| 停止已激活 | state 变 paused/completed；与 release 激活同事务记录包含前后状态、run、release 和生效时间的结构化 audit_event，旧实例／在途仍按租约及撤销栅栏处理 |
| 激活前失败 | 原有效状态保持 |
| 激活后装载失败 | 记录故障，修复或显式回滚，不改成“从未发布” |
| 同 run 发布中 | 新普通命令409 RELEASE_IN_PROGRESS；紧急停止优先协调 |

## 6. 发布、配置分发与撤销

### 6.1 管理接口

| 方法与路径 | 语义 |
| --- | --- |
| `GET E/publish-tasks/{publish_task_id}` | 编译／分发／激活步骤、期望及观测版本、失败原因、区域与实例确认摘要 |
| `GET E/releases` / `GET E/releases/{release_id}` | 不可变发布历史与激活时间、来源审批、输入摘要、配置版本 |
| `POST E/releases/{release_id}:retry` | 只重试可恢复步骤；不可变输入不改，当前依赖不合法则明确失败 |
| `POST E/releases:rollback` | 指定目标历史版本与原因；校验桶回收、归属、撤销、兼容性后生成新发布任务 |
| `POST E/emergency-stops` | 明确 run／服务范围与原因；单调撤销版本，优先发布停止执行租约 |
| `GET E/reservations/{reservation_id}/drain-status` | `reclaim_after`、旧快照失效界限、token／在途窗口、仍未满足的回收条件 |
| `GET E/audit-events`、`GET N/audit-events`、`GET /api/admin/v1/audit-events` | 统一 audit_event 按 environment／namespace／deployment 范围和 audit.read 过滤；deployment 不填虚构 Namespace |
| `GET/POST E/configuration-changes` | 为基线或拓扑版本创建发布变更请求，绑定目标版本、差异和依赖摘要；不借用虚假的实验 run |
| `POST E/configuration-changes/{change_id}:approve` | 审批精确目标版本和差异，记录审批身份；目标或依赖变化须重新校验 |
| `POST E/configuration-changes/{change_id}:publish` | 审批有效后创建发布任务，沿用编译、CAS、租约及回收规则 |

`publish_task_id` 定位 release 发布记录，不另建任务表；artifact URI、摘要、签名及编译版本写 release，完整输入／拓扑／基线／运行快照在不可变对象文件中。配置字段冻结后不可修改，发布状态可演进；config_revision 在环境内唯一。environment 保存活动 head、CAS 版本和只增撤销序号。`publish_task.status=building|distributing|active|failed`；细步骤包括编译、存储校验、readiness、CAS 激活与装载观测。`active` 表示发布指针已激活；独立的 `rollout_status=converging|converged|degraded` 和覆盖率描述实例状态，未知实例不能算作已确认。目标失效或取消保存在 failure code，不把数据库已提交配置伪装为全部实例已装载。

回滚不原地重开旧 release，也不降低发布／撤销序列：创建新 release、config_revision 和 `release_sequence`，以验证通过的历史冻结输入重新编译／包装配置；仅作用域、capability 和摘要一致的内容文件可复用。不得通过回滚复活已经物理复用桶的旧实验。结束时 logical completed 与 physical released 分开。所有仍可能含目标 run 的旧 release 必须关闭续签；回收下界为它们已持久化的最大 max_lease_expires_at + max_context_ttl + max_inflight + clock_skew。证据及上界写 allocation_reservation；无法证明上界就保持 draining，实例 ACK 不能代替该证明。

审计、outbox、幂等各使用一张带 scope_kind 与真实 N/E 约束的统一表。控制面 outbox 消费者以 event_id、目标业务唯一 ID 和 CAS 防重，不增设 consumer_inbox；投递标记不代替副作用幂等，也不承诺 exactly-once。

### 6.2 可信运行配置 API

```http
GET /api/runtime/v1/snapshots/active
Authorization: Bearer <short_lived_workload_token>
If-None-Match: "svc-rank-config-opaque"
```

机器 principal 全局唯一、显式加入 Namespace；身份绑定 namespace／environment／service 及动作，连接使用 TLS，内部调用按组织要求采用 mTLS 和短期工作负载凭证。配置 URL、请求 scope 或自定义头不能覆盖凭证的 namespace/env/service；机器凭证唯一绑定 Namespace＋environment＋service＋principal，动作取凭证上限与当前角色绑定的交集。直接决策角色可以获取获授权依赖的规则投影；执行角色只能解析当前服务值。公开客户端不得调用全规则下载。

projection/bundle 的索引可合入 release 对象包，但每个 service + capability 的下载文件必须有独立授权 URI 和摘要；不能把含其他应用参数的全环境压缩包发给执行服务。

示例 `200` 返回服务投影 manifest；摘要和签名为示意值，不能用来测试验签：

```json
{
  "data": {
    "schema_version": 1, "namespace_id": "prj_shop", "environment_id": "env_prod", "service_id": "svc_rank",
    "config_revision": "cfg_release_42", "release_sequence": 42,
    "hash_protocol": "ab-bucket-sha256-v2", "compiler_version": "compiler_1",
    "created_at": "2026-09-19T15:00:00.000Z", "not_before": "2026-09-19T15:00:00.000Z",
    "expires_at": "2026-09-19T15:05:00.000Z",
    "artifact": {
      "path": "/api/runtime/v1/snapshots/cfg_release_42/projections/projection_rank_42/artifact",
      "projection_id": "projection_rank_42", "digest": "sha256:example", "size_bytes": 18432,
      "signature": {"format": "jws", "alg": "ES256", "kid": "signing_key_1", "value": "example-only"}
    },
    "revocation_revision": 7
  },
  "manifest_signature": {"alg": "ES256", "kid": "signing_key_1", "compact_jws": "example-only"}
}
```

`manifest_signature` 的 JWS payload 是 `data` 的 JCS 规范化字节，使用客户端预置信任的 key 与 ES256 算法白名单验证；未通过验签前不相信其中的路径和租约。manifest 自身必须被签名并与产物摘要、作用域、有效期绑定；不要只签 payload 却让路径／租约可被替换。不可变 artifact 内容不包含会随租约续期而改动的运行有效期，not_before／expires_at 属于签名 manifest；相同内容可签发新 manifest，但不能绕过已生效撤销。详细签名编码、JCS 与 hash 输入见 [SDK 协议](./03-SDK与分流协议.md)。示例有效期不是上线配置承诺，实际期限由租约和回收策略确定。

manifest 是短期签名协议，不逐条落表。签发事务校验当前身份、目标 release 可签发及撤销状态，单调更新 release.max_lease_expires_at，提交成功后才签名返回；失败可留下保守上界，但不能先发签名再补写。停止续签与签发共用同一锁栅栏，覆盖全部相关旧 release。

manifest 返回的 `GET /api/runtime/v1/snapshots/{config_revision}/projections/{projection_id}/artifact` 是独立投影文件路径。旧 `/snapshots/{config_revision}/artifact` 入口仅在可信身份唯一定位一个授权投影时作为别名返回该文件；不能返回全环境包。两条路径都校验服务／capability／投影授权；不能靠知道路径读取其他服务配置。活动 manifest 为 `Cache-Control: private, no-cache`，ETag 至少区分 Namespace、环境、服务投影、发布和租约；`304` 不延长执行授权，SDK 仍检查已缓存的 expires_at。重新授权期限必须发新签名 manifest；产物内容可复用。

SDK 完成完整下载、摘要／签名、Schema 和依赖校验后原子装载，用 `POST /api/runtime/v1/snapshot-acks` 上报 `instance_id, config_revision, projection_id, status=loaded|rejected, loaded_at, sdk_version, error_code?`，幂等键由实例／配置／结果形成。原始 ACK/readiness 观测进入既有遥测，service_environment 只保最近摘要，不建 release_ack 表。ACK 证明该实例的装载事实，不保证业务执行成功，也不证明旧租约全部失效。

`GET /api/runtime/v1/revocations/active` 提供短租约的撤销栅栏与强 ETag，撤销序号单调不降。SDK 缺少有效执行租约时按约定回退或拒绝实验处理，不能继续用长期缓存绕过停止。配置可以包含可公开业务值或受控资产引用，不能包含用户密码、机器密钥等 secret；签名提供完整性，不提供保密性。

## 7. 运行时批量决策

### 7.1 端点与信任边界

`POST /api/runtime/v1/evaluations:batch` 在一次业务决策中，针对一个固定随机化单元批量返回多个参数，可同时包含并行层中的多个实验。首版不在同一请求中混合多个用户。可使用有效配置的可信 SDK 本地决策，或由授权 BFF／服务调用远程决策；二者必须输出同一结构并遵守相同 hash、快照及事件契约。

普通浏览器和移动端只调用所属 BFF 的业务接口，BFF 从登录会话／可信匿名身份获得 `unit.id`，不能相信客户端任意冒用他人 ID。BFF 返回明确允许公开的最终参数值；不转发全量规则、私有服务参数、完整画像或通用机器凭证。用于公共客户端事件的受限凭证不能具有 `contexts:resolve` 或配置下载能力。

评估需 runtime.evaluate；解析需 runtime.context.resolve；配置读取、ACK 与撤销查询需 runtime.config.read。详细调试额外需 runtime.debug 及被展示资源 read。

以下字段为服务端权威：scope、调用 service、当前配置、固定资格、unit 假名、run 与分组。请求中的参数 Key、资格引用与可选 config_revision 只是待授权和验证的选择，不能越权覆盖这些事实。

### 7.2 请求 Schema 与示例

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `request_id` | 是 | 本次逻辑评估的唯一随机 ID；网络重试保持，新的业务决策生成新 ID |
| `unit` | 是 | `{type:"user_id",id:"..."}`；首版只支持可信 user_id；后续单元类型必须先完成实验设计评审 |
| `business_scope` | 否 | authority 获授权的稳定决策范围 ID；缺省只能使用凭证绑定默认值，不能解释为 Namespace 全量规则 |
| `parameter_keys` | 是 | 去重的 Namespace 内 Key 数组，1–200 个；每个 Key 必须允许当前服务读取；只决定返回投影，不裁剪完整分配范围 |
| `scene` | 否 | 业务场景标记，用于可观测和预先约定的测量触发，不替代固定资格 |
| `context` | 否 | 请求级上下文的允许列表；实时设备、位置等不能改写已固定资格 |
| `eligibility_snapshot_ref` | 否 | 可信服务可附 `snapshot_id, eligibility_epoch, proof_token`；平台验签并匹配身份／epoch；缺省从可信快照服务解析 |
| `config_revision` | 否 | 内部需要固定调用链版本时使用；必须仍有执行授权且可解析，不允许强行选过期配置 |

```http
POST /api/runtime/v1/evaluations:batch
Authorization: Bearer <workload_token_for_svc_rank>
Content-Type: application/json
```

```json
{
  "request_id": "eval_request_74a1",
  "business_scope": "scope_home_feed",
  "unit": {"type": "user_id", "id": "business-user-4831"},
  "parameter_keys": ["ranking.temperature", "ranking.timeout_ms"],
  "scene": "home_feed",
  "context": {"request_locale": "zh-CN"},
  "eligibility_snapshot_ref": {
    "snapshot_id": "profile_4831_epoch_9", "eligibility_epoch": "elig_epoch_9", "proof_token": "opaque-trusted-proof"

```

身份服务把原始 ID 转为 Namespace 内稳定 `unit_key`，事件采用同一假名值 `unit.id_hash`。不把原始 ID写入通用日志。固定资格原子首次写入后包含当时缺失字段；不能在旧 snapshot 上补填后来出现的属性，以免破坏同桶互斥证明。可信引用 epoch 不匹配为 `409 ELIGIBILITY_EPOCH_MISMATCH`，不得偷偷新建资格覆盖旧周期。

服务端在既有运行时 KV 中以 `(scope, caller_id, request_id)` 保留原决策及请求摘要，保留期不短于声明的重试窗口；同 ID 同请求重放同一 `decision_id/config_revision/assignments`，不能在重试时使用最新配置重算。同 ID 不同请求 `409 REQUEST_ID_REUSED`。配置和资格在一次评估开始时固定；批量中不得一部分用旧配置、一部分用新配置。

```json
    "issued_at": "2026-09-19T15:01:00.000Z", "expires_at": "2026-09-19T15:02:00.000Z",
    "request_id_expires_at": "2026-09-20T15:01:00.000Z",
    "freshness": "fresh", "degraded": false, "diagnostics": []
  },
  "meta": {"request_id": "req_http_evaluate_1"}
}
```

时间窗口是协议示例；部署能力必须明示实际上限。`assignments` 可以是 0、1 或多个实验，顺序只在本响应中定义 `assignment_index`，跨请求不稳定。分组身份必须用 `(run_id,variant_id)` 关联，不能用数组索引或一个全局 `is_b` 标志。每个参数最终只由一个允许的实验覆盖；若编译或装载发现同一有效路径多重覆盖，拒绝该产物并告警，不能靠数组后者覆盖前者。

`parameters` 只含当前服务获授权的请求 Key。`source=experiment|baseline|emergency_default`；另用响应级 `freshness=fresh|last_known_good` 表示是否在有效执行租约及允许陈旧窗口内使用旧配置。旧配置可能返回 experiment 或 baseline，仍给出其 config_revision 和原分配；过期或被撤销的配置不得标成 last_known_good 继续处理。无命中、暂停或资格不满足使用固定环境基线；远程基线／快照不可用则报 `503 DECISION_UNAVAILABLE`。`emergency_default` 仅用于 SDK 本地采用调用方预先确认的安全值，不能使远程失败响应伪装成成功分组。不得对未知 Key 伪造 null，也不得把 Schema 不符当成默认成功。

原分配不随回退改为对照组。若已有分配但 SDK 实际使用 emergency_default，保留 assignments，参数详情中的 `source` 与 `fallback_reason` 表示实际返回值，`assignment_index=null`；原分配通过该参数对应的 assignment 事实关联。若没有资格或有效配置而无法作出任何可信分配，SDK 的本地降级结果 assignments 为空，并给 `degraded=true` 与明确原因。高风险业务可以要求禁止降级，此时直接失败。

SDK `get`／本接口成功响应只证明查询与分配，不自动计曝光。处理前业务资格触发、实际执行／曝光和结果上报由各自事件定义；同一次决定多个参数不应因每次 getter 调用重复计样本。

### 7.4 重试与投影一致性

本地 authority 仅能在有效签发租约内生成 context，TTL 不超过冻结契约上限；每次 decision/token 不要求同步写 PostgreSQL。租约续发持久化上界，决策及事件事实走既有数据链路。缓存重放不延长原 `expires_at`，不可把已过期 token 用于新执行。对过期的旧逻辑请求重试可以返回原始决策以便恢复关联，但需要新的业务决策时须显式创建新的 request_id；调用链不能静默自行重算。服务端给出重试窗口，客户端超窗不保证幂等重放，应先用内部关联记录恢复业务状态。

不允许通过仅请求本服务参数而改变其他相关层的随机结果。`business_scope` 由控制面登记完整业务决策范围和可参与服务，authority 按该范围构建完整分配，再将 parameter_keys 用作返回投影；服务权限不足不能通过任意 scope 字符串扩大。BFF 的权威决策构建完整、获授权的调用链上下文，再对各服务生成投影；本地直接决策服务只有在身份、hash 协议、配置 revision、资格 epoch／snapshot 均相同的情况下才能声称结果等价。

## 8. 跨服务上下文解析

`POST /api/runtime/v1/contexts:resolve` 消费已有决策，按当前服务权限返回所需值，不再次选组，不读取“最新”实验覆盖。网络载体使用单一 `X-Experiment-Context` opaque token 或约定的 gRPC metadata；MQ 将其放消息 envelope。入口剥离外部伪造载体，校验签名／记录、scope、目标 audience、有效期与撤销栅栏。

```json
{
  "decision_token": "opaque-execution-context-token",
  "parameter_keys": ["ranking.temperature"],
  "request_id": "resolve_request_rank_74a1"
}
```

调用身份是 `svc_rank`；不能凭请求体把自己改成另一个服务。resolve 只访问原 decision 的 business_scope，不允许扩展范围或给原范围外实验补分组。返回沿用第 7 节结构，保持 `decision_id/config_revision/run_id/variant_id` 不变，仅裁剪授权 `parameters` 和对应 assignments，并重建本响应的 `assignment_index`。token 可以是受签名封装的短字段或服务端上下文句柄，不要求业务解析 token 内部；平台不能依靠前端自行声明分组来生成上下文。

`CONTEXT_EXPIRED`、`CONTEXT_REVOKED`、`CONTEXT_SCOPE_MISMATCH` 或依赖 bundle 不可解析时不能调用 evaluate 悄悄补一份新组。按服务约定回退／拒绝，执行事件记录原决策及实际值。各服务参数的授权投影是只读解析，不保证模型和代码都已成功加载；需要整体一致的业务由编排层协调回退，不能把部分执行记为全部成功。

token 的执行有效期与事件验收期限分开。迟到曝光或业务事件携带旧 token 时，接收端查询已保存的决策、当时有效时间与采集策略；不会仅因“现在 token 已过期”拒绝合法历史事件。已过期 token 也不能证明一个发生在失效后的新处理合法，必须校验 `event_time`、服务身份、执行窗口及允许时钟误差。

上下文不在 URL、公开缓存 Key 或全量访问日志中传播；日志只记 decision_id 与脱敏摘要。响应缓存必须包含 Namespace、环境、服务授权投影及决定内容的版本与分组因素，SSR 和 hydration 复用同一次决策，避免缓存把其他分组参数给当前用户。

## 9. 事件接收协议

### 9.1 类型与公共字段

`POST /api/runtime/v1/events:batch` 接收 SDK／BFF／业务服务的持久异步事件。配置查询不顺便上传曝光；只读参数多次查询不得增加主指标样本。事件语义与统计处理详见 [指标生产与分析](./04-指标生产与分析.md)。

| `event_type` | 产生者与含义 | 不能据此推断 |
| --- | --- | --- |
| `qualification` | 在实验处理之前发生的业务资格／机会触发；带冻结 `trigger_id` 和本次事实 `qualification_id`，用于预定分母 | 不能由处理后的点击或成功请求反推资格 |
| `assignment` | 可信决策服务或本地决策 SDK 为 run 记录随机分配；同一 decision 按 assignment 展开 | 分配成功不等于处理执行／曝光 |
| `execution` | 服务实际使用的 bundle、模型、值摘要和 fallback；可包含失败事实 | 实际执行不一定满足已定义的可见曝光 |
| `exposure` | 已满足该 run 预先定义的业务曝光点，标明触发／机会身份与实际处理 | 不以查询、到达层或所有 SDK getter 作为曝光 |
| `business` | 订单、点击等业务事实及更正；可不带 decision/run/variant | 客户端附带的组标签不是可信归因依据 |

`trigger_id` 是运行前冻结的机会／资格触发定义，`qualification_id` 是本次资格判定事实身份，二者互不替代；资格事实与随后 assignment 以明确关联字段连接。

公共 envelope 必填 `schema_version, event_id, event_type, event_time, producer_id, namespace_id, environment_id`；参与归因的事实必填 `unit:{type,id_hash}`，有业务请求时提供 `request_id`，无请求的可信 CDC／账本事件不伪造请求号；可关联时带 `decision_id, run_id, variant_id, config_revision, decision_token`。`received_at` 由接收端写入。接收须有 `event.ingest`；字段中的 scope 必须与凭证绑定一致，producer 必须在该工作负载允许集合中；没有可信来源的 `id_hash` 必须由 BFF 身份通道重建。

assignment、execution、exposure 的 run／variant 从 token 或服务端保存的 decision 校验；payload 不得改写。同一 decision 含多个实验时，为每个被报告 run 提供明确的分配行，不能任取第一组。business 不强制提供实验标签；平台按相同 scope、随机化单元、可信 assignment 与冻结窗口进行 join。

```json
{
  "data": {
    "batch_id": "batch_events_1", "received_at": "2026-09-19T15:01:16.000Z",
    "results": [
      {"event_id": "evt_exec_74a1", "status": "accepted"},
      {"event_id": "evt_order_913", "status": "duplicate"}
    ]
  },
  "meta": {"request_id": "req_events_1"}

```

逐项权限校验不得跨 Namespace／环境放行；同一网关的 producer 白名单也不能扩大参数或事件动作范围。

正常返回 `202`。accepted 表示事件已写入既有数据链路的持久接收日志，不能在仅进入进程内存后 ACK；不表示已完成归因或统计计算。duplicate 表示相同身份及正文已接收；rejected 带逐条 `code, field_path, retryable`。外层 JSON 或鉴权失败则整个请求返回 4xx；超大批次 413。服务不可用而无法持久接收时返回 503，重试保留原 event_id；若 ACK 在网络丢失，完整重传不会产生新事实。

传输去重键为 `(namespace_id,environment_id,producer_id,event_id)`。相同键不同正文进入冲突隔离并返回 `EVENT_ID_PAYLOAD_MISMATCH`，不能覆盖原记录。业务去重另使用 `(scope,source_system,source_event_id,source_version)`；订单重发不能仅换 event_id 就重复计收入。退款／调整采用独立 `adjustment_id` 与关联业务身份，不能把每次重试都算作新增扣减。事件时间超出允许范围、未知 Schema 或无法验证归属进入隔离，保留可审计原因。

逐项 rejected 仅对 `retryable=true` 条目保持原 ID 重试；修正内容后使用新的更正事件身份并关联原事件，不允许更换正文复用旧 ID。SDK 采用有界缓冲、退避、磁盘队列或组织标准采集代理，达到容量上限计丢失量并报警，不能无限占用业务内存或阻塞主链路。

## 10. 指标目录、分析计划与结果查询

指标版本和分析计划是固定运行契约。它们不能在看到结果后被原地修改为“更好看”的口径。首版计划、统计方法和数据质量约束由 [指标方案](./04-指标生产与分析.md) 定义，API 只引用受支持的版本化方法，不接受浏览器提交任意 SQL。

### 10.1 计划编写、校验与冻结

计划从草稿的 `analysis_plan_draft` 创建：通过 `PUT E/experiment-drafts/{draft_id}` 随其他内容保存，使用同一 If-Match；允许暂时不完整。`:validate` 检查计划并返回字段定位；`:submit` 必须通过全部计划检查，在创建 run、预留和 change_request 的同一事务中，把完整计划、指标定义及策略实现版本写入 experiment_run.contract_snapshot；analysis_plan_version_id 是其中的固定逻辑标识，不另建计划／指标关联表。不存在“先提交运行、之后补分析计划”的生产路径。提交响应和 run 详情均返回这个 ID；若随后审批退回，新草稿包含可编辑副本，原计划不变。

| 字段 | 提交时约束 |
| --- | --- |
| `design` | 首版固定 `fixed_horizon`；序贯检验不接受仅靠字符串启用 |
| `randomization_unit, identity_namespace_id` | 必须匹配运行和可信身份策略；不能用事件数量替代随机化单位 |
| `population_spec` | ITT 或预注册处理前触发群体；冻结 trigger 定义、排除政策与资格依据；祖先条件由服务端绑定 |
| `enrollment_window` | 明确 `start_at < end_at`、UTC；启动延误不得自动平移／延长计划 |
| `outcome_window` | 每单元自首次分配起固定观察 W，`duration_seconds > 0`；暂停后已入组观察继续 |
| `lateness_policy` | 明确传输迟到 L 与每个指标的业务更正 H；不能用 watermark 替代源完整性证明 |
| `metrics` | 恰好一个主指标，显式必需护栏，可另有次要／诊断指标；每项固定 metric_version_id、完整定义、方向、假设及方法 |
| `alpha, power, mde, mde_scale` | 有限数；`0<alpha<1`、`0<power<1`、`mde>0`，MDE 说明绝对／相对；不同于流量 bps |
| `sample_plan` | 各组目标独立随机化单元数、历史基线与方差依据、计算器版本；与实际权重、指标分布和比较族一致 |
| `comparison_family` | 正式假设集合、唯一 control、处理对对照比较、多重校正与区间政策；不隐式追加全部组间比较 |
| `stopping_rule, guardrail_policy` | 固定结束规则、样本不足行为、预授权安全止损与提前停止后的结论限制 |
| `allocation_schedule, quality_policy_version_id` | 冻结允许的流量节奏及质量门禁；扩量也必须符合原计划，不得为了显著性事后改变节奏 |

### 10.2 目录与结果 API


| 方法与路径 | 请求／返回重点 |
| --- | --- |
| `GET/POST N/metrics` | 指标目录身份、名称、负责人、业务说明 |
| `GET/POST N/metrics/{metric_id}/versions` | GET 仅返回当前受支持版本；POST 带 If-Match 更新 metric 当前定义、生成新版本 ID 并审计；已冻结 run 不变 |

| `POST R/analysis-jobs` | 申请计算／迟到重算；传 cutoff、原因和受支持模式，异步返回创建时固定的 analysis_job_id／analysis_run_id |
| `GET E/analysis-jobs/{analysis_job_id}` | 调度进度、固定的 analysis_run_id 和失败原因；预分配 ID 不代表结果已完成 |
| `GET E/analysis-runs/{analysis_run_id}` | 冻结 `analysis_plan_version_id, data_snapshot_id, cutoff, code_version` 和结果元信息 |
| `GET E/analysis-runs/{analysis_run_id}/metrics` | 分组样本、指标估计、绝对／相对差、置信区间、校正检验与结论状态 |
| `GET E/analysis-runs/{analysis_run_id}/quality` | SRM、丢失、归因失败、迟到、回退、成熟窗口等质量检查 |
| `POST E/analysis-runs/{analysis_run_id}/exports` | 异步导出授权聚合报告；不提供任意用户明细导出 |

metric 只保存当前定义。新提交只选当前受支持 metric_version_id，旧稿版本过期需重新校验，不能静默换版；旧口径从获授权 run 的冻结计划读取，不能凭旧版本 ID 查询不存在的历史表。

analysis_job 创建时即固定 analysis_run_id，执行与重试不更换；首次执行前冻结 data_snapshot_id、input manifest、源快照／offset、水位、cutoff、code_version 和 seed，重试复用，不到终态才挑选输入。成功结果的 URI／摘要及元信息不可覆盖；更正、换输入或代码须新建 job。创建去重由 idempotency_record 控制：有效期内同 Idempotency-Key 重放原 job，新 key 可创建新 job，即使请求正文相同；request_digest 仅作校验和追溯，不作为永久唯一键。

列表、结果、缓存和导出都绑定 Namespace／环境及当前授权对象集合；看得到实验不自动获得 result.read，result.read 不自动获得 result.export。计算任务固定目标范围；执行及下载前重检撤权，临时链接不能绕过鉴权。

`analysis_run_id` 是分析计算身份，不能和实验 `run_id` 或调度 `analysis_job_id` 混用。重算生成新的 analysis_job_id 和 analysis_run_id，并用 `supersedes_analysis_run_id` 关联同 run 的成功旧结果，禁止自指；旧报告只读保留，不覆盖数值。预览与最终结果必须显式 `result_status=invalid|insufficient|provisional|final`，任务运行成功不代表统计结论有效；同时存在多个阻断时以 `invalid > insufficient > provisional > final` 判定展示状态，并通过 `quality_findings[]` 保留各条原因。

```json
    "analysis_run_id": "arun_feed_20260920_1", "run_id": "run_feed_1",
    "analysis_plan_version_id": "apv_feed_1", "data_snapshot_id": "ds_20260920_1",
```

## 11. 错误协议、限流与可观测性

错误媒体类型采用 `application/problem+json`，字段兼容 [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)，使用扩展字段携带稳定业务码、重试属性和表单定位。成功响应有 data envelope，错误体不再多包一层 `error`。

```http
HTTP/1.1 422 Unprocessable Content
Content-Type: application/problem+json
```

```json
{
  "type": "urn:explab:problem:validation-failed",
  "title": "实验配置校验失败", "status": 422,
  "detail": "实验组参数源码包含重复字段，草稿原文已保留。",
  "instance": "urn:explab:request:req_validate_8", "code": "VALIDATION_FAILED",
  "request_id": "req_validate_8", "retryable": false,
  "errors": [
    {
      "code": "JSON_DUPLICATE_KEY", "field_path": "/variants/1/parameters_source",
      "section": "variants", "variant_id": "var_treatment", "parameter_key": "ranking.temperature",
      "source_pointer": "/ranking.temperature", "line": 4, "column": 3,
      "message": "同一对象重复声明 ranking.temperature"
    }
  ]
}
```

`field_path` 是请求外层 JSON 的 Pointer；`source_pointer` 定位字符串内解析对象，无法解析时可缺省并依靠行列定位。Pointer 转义遵循 [RFC 6901](https://www.rfc-editor.org/rfc/rfc6901.html)，`/` 转义为 `~1`、`~` 转义为 `~0`；Key 中的点是普通字符，不能按点拆路径。行列按源码中的 Unicode 标量计数并从 1 开始，前端负责转换为编辑器的 UTF-16 偏移。错误不回显完整原文、画像、token 或秘密参数。

| HTTP | 示例 code | 客户端处理 |
| --- | --- | --- |
| 400 | `MALFORMED_JSON / INVALID_CURSOR` | 外层请求不合法，修正后新请求；草稿内错误源码不属于此项 |
| 401 | `UNAUTHENTICATED` | 凭证失效；刷新一次，保留幂等身份 |
| 403 | `FORBIDDEN / ROLE_NOT_DELEGABLE / CONTEXT_SCOPE_MISMATCH` | 不自动切换其他服务身份重试 |
| 404 | `RESOURCE_NOT_FOUND` | 对象不存在或不可见；不得自动创建同名资源替代 |
| 409 | `ALLOCATION_CONFLICT / PLAN_STALE / POLICY_CHANGED / RELEASE_IN_PROGRESS / REQUEST_ID_REUSED` | 返回安全的冲突范围、当前依赖版本和建议操作；重读／重校验；只有明确暂态码可退避重试 |
| 410 | `CONTEXT_EXPIRED / CONTEXT_REVOKED` | 停止用该上下文执行；按既定回退规则处理，历史事件单独校验 |
| 412 | `REVISION_MISMATCH` | 暂停自动保存，保留本地正文；获取新 ETag 后人工合并或另存新稿 |
| 413 | `PAYLOAD_TOO_LARGE` | 拆小事件批次或按上限缩减源码；不得静默截断 |
| 422 | `VALIDATION_FAILED / INVALID_RESOURCE_SCOPE / PARAMETER_NOT_ACTIVE / ANALYSIS_PLAN_INVALID` | 定位具体字段修正；不原样自动重试 |
| 428 | `PRECONDITION_REQUIRED` | 先读资源 ETag，再发条件更新 |
| 429 | `RATE_LIMITED` | 按 Retry-After 与调用方预算退避，重试身份不变 |
| 500/503 | `INTERNAL_ERROR / DECISION_UNAVAILABLE / INGEST_UNAVAILABLE` | 有界重试；请求可能已提交，应以幂等身份恢复，不能假定从未执行 |

`GET /api/admin/v1/capabilities` 和 `GET /api/runtime/v1/capabilities` 返回当前身份范围支持的 API／事件／配置 Schema 版本、请求大小、批次、文本深度、重试和租约上限。它们只公开契约限制，不暴露实例拓扑或凭证。已知协议不兼容要在装载／请求开始前拒绝，不让 SDK 在字段未知时猜测桶分配含义。

按部署总预算、Namespace、环境、服务和路由能力限流，管理大查询、配置下载、决策、事件分别计额；不能因一个导出任务阻塞线上决策。服务端透传并校验追踪上下文，日志关联 `request_id/decision_id/publish_task_id/analysis_run_id`，记录延迟、结果码与脱敏 scope；严禁以完整 payload 代替结构化审计。

## 12. 兼容策略与接口验收

v1.3 收敛控制库存储，不重写已有 opaque ID；Namespace 字段／路径更名仍属于未实施草案校准。生产上线后，`/v1` 内只做向后兼容的字段增加；改变类型、缺省语义、单元身份、分流算法、event 去重或枚举含义需新版本／显式能力协商。SDK 遇到不能理解的运行关键枚举或 hash_protocol 应拒绝产物；管理展示客户端可以把新的展示状态显示为未知，但不能擅自执行状态命令。旧 camelCase/localStorage 数据只在迁移层翻译，不让一个生产端点同时接受两个语义不一致的字段。 本设计使用显式版本 `ab-bucket-sha256-v2`；它与 `ab-bucket-sha256-v1` 的输入编码不同，配置、缓存与验证向量不得混用，也不得将 v1 产物直接重标为 v2。

接口验收至少包含以下可观察结果：

1. 两个编辑者持同一 ETag 保存，只有一个成功；另一个 412 且原文不丢。无效组内 JSON 可保存，提交必须返回准确定位。
2. 相同 source_draft_id 与幂等键重复提交只生成一个 run／预留；审核退回获得新 draft_id，旧提交重试仍返回旧 run。
3. 多个请求并发抢最后可用桶，事务串行验证无双占；参数激活、拆层、子域创建与实验提交同时发生也保持完整分区。
4. 受众预览后祖先或占用改变，提交重校验；unknown 证明不放行相交桶；任意前端画像不能更改固定资格。
5. 审批后依赖摘要改变，启动拒绝旧批准；发布受理不伪称实例生效；结束后 draining 未满足时相交桶不可复用。
6. 一次评估多个层返回 assignments 数组；同 request_id 重试不换配置；resolve 在不同服务仅投影授权参数且不换组。
7. 短 token 到期后不能继续执行；允许窗口内合法历史曝光仍可核验接收；前端伪造 run／variant 被拒绝或隔离。
8. accepted ACK 只发生在持久化后；网络丢 ACK 重试不重复计数；相同 event_id 不同 payload、重复订单和独立退款各按协议处理。
9. 无业务事件的合格分配单元保留统计分母；零样本返回 null／insufficient_data；迟到重算产生新 analysis_run_id，历史结果不覆盖。
10. 跨 Namespace、环境及服务投影的直接对象访问、游标复用和配置缓存均无法越权；公开客户端无法下载规则或机器凭证。

11. 有成员无角色、只有实验 edit 无依赖 use、approve 无 edit、环境限定目录写、自提权、撤权竞态及隐藏对象查询均按动作／范围拒绝；授权变化使旧游标失效；首期直查当前权限，不依赖 allow 缓存。
12. 跨 Namespace 同一用户可分别入组；共享首页团队在同一 Namespace 合作，跨团队引用逐项授权。Namespace 改名不改 ID、hash 输入字节或桶号。
13. group 主体首期拒绝；资源自身环境与授权过滤不混用；历史 run／基线／指标查询读取冻结快照。签发上界提交前不得返回 manifest，关闭续签与并发签发按同一栅栏串行；分析重试复用固定输入，更正新增 job。

以上是待实现服务的契约验收清单，不表示这些接口已经通过测试。当前仓库的前端构建与测试不能替代数据库并发、运行鉴权、跨语言 SDK 或真实采集链路验证。
