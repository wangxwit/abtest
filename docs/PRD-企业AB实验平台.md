# 企业 AB 实验平台 PRD

设计 v1.2 · 2026-09-23｜实现基线：v23 前端原型

本文定义产品范围、路线图与验收。页面和对象见[产品设计](./平台文档/01-产品设计.md)，技术契约见[服务端方案](./服务端技术方案/README.md)。

## 1. 目标

统一实验身份、参数范围、分流、执行证据和分析口径，让团队能回答：谁接受了什么变化、实际是否执行、结果是否可信、能否扩大流量。

| 问题 | 产品目标 | 后续试点衡量 |
| --- | --- | --- |
| 多端自行分组，处理不一致 | 一次决策、跨服务复用 | 错组率、实际执行率、回退率 |
| 配置与结论难以重建 | 冻结配置、指标及分析版本 | 正式结论可复现比例 |
| 资源与职责边界不清 | Namespace 与资源授权 | 越权检查、审计完整率 |
| 流量与参数相互冲突 | 层域规则、可解释分配 | 提交冲突率、准备时长 |
| 把演示或显著性当结论 | 数据质量和成熟度门禁 | 通过质量检查的正式结论比例 |

当前没有企业基线、容量或投入数据，不承诺固定收益、SLA 和交付日期。首批试点先记录准备时长、接入成本和质量指标，再确定改善目标。

## 2. 交付范围与状态

| 范围 | v23 状态 | 后续建设 |
| --- | --- | --- |
| 应用与参数 | 应用登记、私有标签、注册 pending、完整归层 | 定义版本、环境激活、机器身份与接入验证 |
| 层域与流量 | 递归层域、10,000 碎片桶、固定资格模拟 | 后端事务、持久资格、发布与回收 |
| 受众 | 独立画像定义、AND／OR、固定版本、引用导航 | 真实画像供应与资格快照 |
| 实验配置 | 2–20 组、唯一对照、本地草稿、完整 JSON | 冻结 revision/run、真实审批和发布 |
| JSON 编辑 | 源码、专注模式、只读目录、组间结构差异 | 基线覆盖、表格、可编辑树、Schema、导入 |
| 管理 | 层域负责人、期限、页面到期提醒 | Namespace、全局账号、RBAC、审计 |
| 结果 | 演示指标、报告及导出 | 事件采集、指标生产、统计引擎与结果权限 |

原型没有真实后端、Namespace 管理、RBAC、管理 API、生产 SDK 或真实统计分析。状态按钮不会影响线上服务，负责人不是授权，演示人数和显著性不能用于业务决策。

## 3. 用户与职责

| 使用者 | 任务 |
| --- | --- |
| 产品／增长 | 假设、主指标、实验配置与业务判断 |
| 业务研发／算法 | 参数执行、版本兼容、上下文与回退 |
| 数据人员 | 指标口径、分析计划、质量诊断与复现 |
| 审批者 | 审查指定版本、风险和发布条件 |
| Namespace 管理员 | 成员、可委派授权、资源边界与治理 |
| 平台管理员 | 全局身份、角色模板、平台协议与运行保障 |

角色分工不自动产生权限；真实授权按[05 Namespace 与权限设计](./服务端技术方案/05-Namespace与权限设计.md)执行。

## 4. 资源与授权模型

```text
单企业平台：全局账号、用户组、角色模板
└ Namespace（直接承接旧项目，不再叠加 project／space）
  ├ 应用 → 参数、应用私有标签
  ├ 画像属性、受众、指标目录
  └ 环境 → 根域 → 唯一根路由层 → 子域
                                      └ 参数层 → 实验／子域（递归）
```

Namespace 是实验资源与授权作用域，不是团队同义词，不设租户实体。账号可加入多个 Namespace；平台账号与业务 `user_id` 分离。不同 Namespace 的资源、配置、权限和分桶空间独立，但业务用户可能同时参加多个 Namespace，流量及效果不自动隔离。

跨 Namespace 不直接引用参数或层；同一运行参数不能多处竞争控制。独立招聘、房产、本地生活流程可各设 Namespace，共用首页的联合控参应在同一消费者 Namespace 内按团队授权。

| 权限要求 | 产品约束 |
| --- | --- |
| 成员只准入 | `namespace_member` 不自动看全部资源 |
| 角色多次绑定 | 动作集 + 资源范围 + 可选环境限制；用户／组均可绑定 |
| 最小授权 | 默认拒绝、allow 并集、无显式 deny；子级只读不能覆盖父级编辑 |
| 有限继承 | 应用→参数、环境→域→层→实验；引用边不继承 |
| 分离职责 | 目录管理与 use、层 manage/use、实验 edit/approve/publish、结果 read/export 分离 |
| 委派边界 | 平台管理全局模板；Namespace 管理员仅授可委派角色和范围 |
| 后台执行 | 列表过滤、逐操作校验、审计；owner／创建者／标签不自动赋权 |

多资源操作按阶段检查全部必要权利；完整配置的编排、提交和发布须检查资源使用权，未完成草稿可先保存。审批要求相关依赖 read + approve，不要求 edit/use；发布再验生产授权和审批。环境授权不授目录全局编辑；机器凭证按 ns/env/service/action 限定。

## 5. 必须保留的业务规则

1. 应用管理是参数入口；参数 Key 在 Namespace 内唯一，标签应用私有，画像不填写来源应用。
2. 根域只有一个路由层且只承载子域；同域参数完整且唯一归层，子域继承父层全部参数。
3. 子域创建只生成一个初始参数层；空层可保存但不能建实验或子域。
4. 参数先 pending，再在目标环境原子完成全部受影响归层后 active；依赖未结束实验或子域时不能直接转移。
5. 每层 10,000 桶，按空闲总量组合碎片，不移动旧桶；直接实验和子域共账本。
6. 固定受众版本包含全部祖先条件；AND／OR 只有可证明互斥才复用桶，unknown 保守处理，不换桶补量。
7. 实验 2–20 组、唯一对照、稳定组 ID、正整数基点合计 10,000（100%）；各组相同顶层 Key 集。
8. 参数组合约束保持下线；类型、合法 JSON、作用域及生产可执行性校验保留。
9. 跨服务复用同一 decision；assignment 不等于 exposure，分配后失败不能从主分析随意剔除。
10. 生产参数值、权重、资格和分析计划变更产生新 run；不得静默修改运行含义。

## 6. 核心流程

```mermaid
flowchart LR
  A[登记应用与参数] --> B[完整归层]
  B --> C[选择层与固定受众]
  C --> D[分组和完整配置]
  D --> E[检查与预留]
  E --> F[审批指定版本]
  F --> G[发布并观测执行]
  G --> H[成熟数据分析]
  H --> I[业务决策与归档]
```

前五步在原型中仅有本地交互；后续生产流程需要后台和真实数据。草稿不占桶，提交才重新检查并预留。原型四区工作区可自由切换，错误原文可保存但不能提交。

共享首页日常实验按独立参数能力分层，强耦合组合进入根路由兄弟联合域。正交分配的平均收益不能相加；画像反馈、共享训练及供需干扰另行设计，见[联动方案](./联动实验设计.md)。

## 7. 生产结果与决策要求

- 运行前固定主指标、护栏、目标样本、观察窗、停止规则及多组比较方案。
- 记录分配、处理前资格、实际执行、曝光和业务结果；主分析按预定入组与随机化单元进行。
- 结果展示样本、效应、区间、质量状态和成熟度；显著不等于值得发布，不显著不等于等效。
- SRM、身份污染、缺数或观察窗未成熟时阻断正式胜出结论；严重故障仍可安全停止。
- 固定周期分析不能反复查看直到显著；序贯、CUPED、集群和时间切换须独立验证。

详细统计设计见[04 指标生产与分析](./服务端技术方案/04-指标生产与分析.md)，本 PRD 不另定义一套计算协议。

## 8. 路线图与验收

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| 已有原型 | 目录、层域、草稿、分组、源码与模拟 | 现有记录见 VERIFICATION，不代表生产通过 |
| 1. 范围与权限 | Namespace、身份、角色、目录和环境资源 | 跨 Namespace／环境越权、委派越界、引用越权均被拒绝；列表过滤与审计可验证 |
| 2. 控制面 | 冻结版本、事务预留、审批、编译和发布 | 并发冲突无重复占桶；审批绑定内容；激活与回收可追踪 |
| 3. 首条业务链 | SDK、资格快照、上下文和真实执行 | 跨语言分桶一致；离线、过期、回退、缓存和跨服务联合处理通过 |
| 4. 数据与 A/A | 事件、指标、质量和分析 | 去重与迟到可重算；A/A、SRM、区间覆盖和样本成熟验证 |
| 5. 试点与扩大 | 低风险实验、应急流程、复盘 | 从请求到执行、结果与结论闭环；容量和 SLO 经实测确认 |
| 后续优化 | 编辑基线／表格／树、更多运行时与统计方法 | 各能力独立验收，不以原型展示代替 |

关键验收还包括：碎片桶可用且旧桶稳定；新参数不会部分激活；非重叠分支不误称全局隔离；固定资格缺失不补采；20 组与大 JSON 的隐藏内容仍完整校验；模板变化不修改旧配置。

## 9. 风险与待确认

| 风险／未知 | 上线前处理 |
| --- | --- |
| ID、真实画像、曝光口径不一致 | 确定可信来源和随机化单元，冻结埋点契约 |
| 多 Namespace 控制同一运行参数 | 明确唯一控制归属，迁移后再接入 |
| 画像反馈、模型训练、供需竞争 | 评估污染路径、实验单元和状态隔离 |
| QPS、配置体积、存储与语言未知 | 先盘点现有设施，再压测确定容量和部署 |
| 本地原型被误用生产 | 前后台均明确能力状态，服务端另行实施 |

历史交付和验证集中于 [VERIFICATION](./VERIFICATION.md)，早期设计见 [superpowers 规格](./superpowers/specs/2026-09-06-ab-platform-design.md)。当前设计优先，不继续累积版本流水账。
