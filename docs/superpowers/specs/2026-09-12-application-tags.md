# 应用私有标签设计

v10 · 2026-09-12。用户已明确要求标签属于应用，当前应用只能看到自己的标签。本文件记录已授权设计，不增加审批步骤；v9 应用内参数维护设计保留为历史。

## 范围与关系

- 标签以 `serviceId` 唯一归属应用，ID 全目录唯一，名称在应用内按去除首尾空格、转小写后唯一。不同应用可有同名但不同 ID 的标签。
- 标签读取、创建、筛选和单项／批量维护均带当前应用范围。参数只能绑定所属应用的标签，核心写入也必须拒绝越界关联。
- 参数继续在所属应用的“参数”页签维护，不新增全局参数页。应用内注册固定当前服务。
- 创建实验保留跨服务选参。标签筛选先选应用，只显示其私有标签；切换应用清除标签筛选，保留跨应用累计的已选参数。保存固定 `parameterKeys`，不保存动态标签表达式。

## 旧数据迁移

目录升级到 `schemaVersion: 2`。精确旧共享目录在加载或显式迁移时，按实际参数所属应用拆分稳定 ID 的私有标签副本，保留名称、颜色和关联。旧标签以 `legacyTags` 隐藏归档；未归属参数保留 `pendingTagIds`，普通 `tagIds` 为空。认领后在目标应用复用同名标签或创建私有副本并清除 pending。未引用旧标签保留归档，不暴露给应用标签列表。

现代目录严格校验，不自动修复跨应用引用。无效原数据或迁移写入失败应保留原存储、显示加载错误并阻止继续保存。迁移、标签维护与认领不改变已有实验 Key、取值、层域关系和分桶。

这是本地原型的数据与页面范围约束，不代表生产 RBAC。真实 SDK、凭证、服务迁移、项目模板与多标签页并发保证不在本轮范围。验收标准见[实施计划](../plans/2026-09-12-application-tags.md)；本轮自动化 100/100、构建与核心浏览器验收通过，证据及未执行项见 [VERIFICATION](../../VERIFICATION.md) 的 v10 记录。
