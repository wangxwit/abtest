## 实施顺序

1. 为旧拓扑派生明确示例服务与绑定，未知 custom 保持待归属；增加 catalog 校验及候选配置接口。
2. 实现应用登记和详情五页签，分别保存三环境 direct／delegated，保持运行状态待验证。
3. 参数注册增加必选服务与多标签，支持应用入口预填和表单内先登记应用；参数定义与归属整体保存。
4. 全部参数增加服务／标签检索、单项与批量标签管理、历史待归属认领。
5. 新建实验移除端类型选择，使用固定 Key 选参、服务自动汇总和独立 parameterRules；继续读取旧 coordination。
6. 合并为一级应用管理，统一规范路由和旧入口兼容；检查嵌入页面标题与登记入口。
7. 完成自动化、构建及浏览器验收，把实际结果写入 VERIFICATION，修正失败后再交付。

- `npm test` 执行全部 `tests/*.test.mjs`，文档更新时清单为 79 项；新增导航检查后以实际执行数量为准。
- `npm run build` 完成 TypeScript 检查及 Vite 构建；记录实际错误、警告与输出，不把 bundle 大小解释为性能验证。
- 检查旧拓扑恢复、未知 custom 待归属、服务唯一绑定、重复／无效目录引用、三个环境独立、网关缺失／自委托／环、标签批量修改、固定实验 Key 不变和注册原子性。
- 验证新局部组合规则、旧 coordination 兼容、现有分桶与参数取值保持不变。不得以标签匹配绕过层范围。

## 浏览器验收标准

| 场景 | 通过条件 |
| --- | --- |
| 合并导航 | 只有一个一级“应用管理”；应用目录、详情和全部参数可切换，规范深链可刷新，旧入口仍可到达 |
| 登记应用 | 嵌入目录与详情都可操作；必填／重复标识提示明确，保存后详情与目录一致 |
| 环境配置 | 登记 gateway 后可为一个应用的测试环境委托它；开发与生产不变化；刷新仍保留，全状态仍待验证 |
| 参数注册 | 应用入口预填服务；全部参数入口必须选服务，表单内登记新应用后可继续；类型和递归归属错误被阻断 |
| 服务及标签 | 单参数多标签、跨服务分类、批量追加／移除／替换可保存；旧 custom 待归属可认领，已明确归属不可直接迁移 |
| 选参创建 | 服务与标签联合筛选，多标签任一匹配；只批量加入层内已归属项，不覆盖已有 A/B 值，详情自动显示涉及服务 |
| 规则与快照边界 | 组合违例阻断；保存后标签变化不增删实验参数；不宣称项目模板或运行时默认值快照存在 |
| 可访问性及布局 | 表单键盘可操作，错误可定位，模态 Esc／焦点行为正确；窄屏关键操作可达，无页面水平溢出 |
| 真实状态边界 | 运行观测显示无真实数据；没有可用凭证、手动连通按钮或模拟数据伪装的验证成功 |

浏览器验收已由主执行者执行，覆盖上述关键流程。测试操作使用独立演示数据，不覆盖用户已有应用、参数或实验配置；最终状态和已知限制记录于 [VERIFICATION](../../VERIFICATION.md)。
